# テストの計画シート

手順 4 で、この型を埋めて利用者に見せ、確認を取る。確認が取れたら、判定の基準はもう変えない。

```markdown
# テスト: [短いタイトル]
作成日: YYYY-MM-DD / 確認した人: [名前]（YYYY-MM-DD）

- 対象: [アカウント名 / サイト URL / 広告キャンペーン / アプリ]
- 伸ばす数字（1 つ）: [例: 予約の件数]
- 対象の段階: [例: ページを見た → 予約を始めた]
- 点数: 効果の大きさ ◯ / 確かさ ◯ / やりやすさ ◯ → 合計 ◯

## 仮説
もし [変更内容] をすれば、[対象の人] の [数字] が [方向・量] 変わる。なぜなら [根拠]。

## 計測する数字
- 主な数字: [例: 予約を始めた人の割合]
- 悪くしてはいけない数字: [例: 予約のキャンセル率、問い合わせの件数]
- どこから取るか: [例: GA4 の探索レポート / 予約台帳の CSV / 広告の管理画面の CSV]
- 単位と数え方: [例: 1 件 = 予約完了。割合は 0〜100 の % で記録]

## 進め方
- 方式: [A/B（半分ずつ）/ 複数パターン同時 / 前後比較]
- パターン: A = 現状 / B = [変えた 1 か所] /（C = [別の 1 か所]）
- 揃える条件: [期間・配分・流入元・予算]
- 期間: [◯ 週間、または件数が届くまで]
- 案ごとに必要な件数: [◯ 件]

## 判定の基準（始める前に決める。あとから変えない）
- 成功の条件: 主な数字が [+◯%] 以上、かつ悪くしてはいけない数字が悪化していない
- 中止の条件: [例: 主な数字が −◯% 以下 / 悪くしてはいけない数字が ◯ を超えた]
- 判定する日: YYYY-MM-DD（件数が届いていなければ「まだ分からない」）

## 結果（終わってから書く）
- 判定: [勝ち / 負け / まだ分からない]
- 数字: [A の値 → B の値、件数、意味の文]
- 学んだこと / 次にやること: [ほかへ広げる / やめる / 派生のテスト]
- 元に戻す条件（勝ちのとき）: [例: 翌月の主な数字が A の水準を下回ったら戻す]
```

## 書くときの注意

- **1 パターンで変えるのは 1 か所だけ。** 見出しと写真の両方を試すなら、見出しだけ変えた B と写真だけ変えた C に分け、A と同時に並べる。
- **パターンを増やすと 1 パターンあたりの件数が減り、判定までの期間が延びる。** 比べるパターンが多いほど、偶然よい数字が出ただけの案が勝ったように見えやすい。
- **計測する手段が無い数字は使わない。** 「どこから取るか」が書けない数字は、主な数字にも、悪くしてはいけない数字にもしない。

## 段階の並べ方（手順 2）と点の付け方（手順 3）

- 段階の例: 予約ページは「ページを見た → 予約を始めた → 予約を終えた」、広告は「表示された → クリックした → LP を読んだ → 申し込んだ」。取れない段階は「未取得」と書き、対象に選ばない。
- 点は、効果の大きさ（うまくいったとき数字がどれだけ動くか）・確かさ（過去のテストや顧客の声の裏付け）・やりやすさ（作る手間・元に戻しやすさ）を 1〜10 点で付け、理由を 1 行ずつ書く。
