# トレンド便乗（見つける → 判定する → 投稿案）

話題に便乗すると、ふだん届かない人にも投稿が届きやすくなる。一方で、便乗の仕方を誤ると短時間で批判が広がる。この Skill は、**「便乗できるか」より先に「便乗してよいか」を判定する**。

## 前提

- ブランドナレッジ（何者か、持ちネタ、トンマナ、禁止表現）があれば先に読む。無ければ、自社の持ちネタ（看板商品・季節の企画・場所の特徴）を利用者に確かめる。
- 話題は鮮度が短い。見つけてから投稿案までを 1 回の実行で出す。定期実行にするなら毎日 1 回（朝）。

## 手順

1. **公開の面から話題を拾う。** Yahoo!リアルタイム検索・Google トレンド・期間を 24〜72 時間に絞った Web 検索を見る。TikTok Creative Center は人が開いて記録した分だけを使う。話題ごとに URL と見た時刻を付ける。面の一覧と各媒体の API の状況は [references/sources-and-apis.md](references/sources-and-apis.md)。
2. **便乗してよいかを判定する。** なぜ話題になっているかを一次情報で確かめてから判定する。迷ったら便乗しない。

   | 判定 | 基準 |
   |---|---|
   | 便乗しない | 災害・事故・訃報・事件 / 係争中の話題 / 個人への攻撃 / 宗教・政治の対立 |
   | 慎重に扱う | 他社の炎上 / 権利のある音源や映像（商用アカウントで使える範囲を確かめる）/ 真偽が固まっていない速報。確かめられるまで案にしない |
   | 便乗してよい | 季節・天気・地域の話題 / 食べ物・場所・企画の形式など肯定的な流行 / 業界の明るいニュース |

3. **ブランドとのつながりを 1 行で書く。** 「[話題] × [自社の持ちネタ]」の形で言えない話題は案にしない。
4. **投稿案を書く。** 文面か動画の企画に、いつまでに出す価値があるか（48 時間以内 / 週内 / 季節もの）を添える。
5. **見送った話題も理由と一緒に残す。** 便乗する話題が無い日は「今日は便乗する話題なし」と書き、季節の定番ネタの案だけを返す。

## 守ること

- 投稿はしない。案を人に渡すところで止める。
- TikTok・Instagram・X の画面を自動で集めない（各社の規約が禁じている）。
- 根拠の無い「話題になっているらしい」を案の前提にしない。取れなかった数字は「未取得」と書き、推定で埋めない。
- 判定（手順 2）を飛ばして投稿案を書かない。便乗する話題が無い日に、案を無理に作らない。

## 出力の型

```markdown
# トレンド便乗の案（YYYY-MM-DD HH:MM 時点）

## 一言でいうと
[便乗する案が何本あるか / 今日は便乗する話題なし]

## 投稿案
### 案 1: [話題] × [自社の持ちネタ]
- 話題の根拠: [URL]（見た時刻）/ 言及の規模: [見えた数字。無ければ未取得]
- 判定: 便乗してよい（理由: [  ]）
- 出す期限: [48 時間以内 / 週内 / 季節もの]
- 文面 / 動画の企画: 
- 出す前に人が確かめること: [権利・事実・トンマナ]

## 見送った話題
| 話題 | 判定 | 理由 | URL |
|---|---|---|---|

## 取れなかった面
- [面]: 未取得（理由と、人が見て記録する方法）
```

## フォールバック先

- 公開の面が開けない / TikTok の記録が無い: 開けた面だけで作り、開けなかった面を「未取得」と書く。自動では集めず、人が見て記録するための表（[references/sources-and-apis.md](references/sources-and-apis.md)）を渡す。
- 自社の持ちネタが分からない: ブランドナレッジを先に作る（brand-knowledge-from-url）か、利用者に 3 つ挙げてもらう。
- 「このまま投稿して」と頼まれた: この Skill では投稿しない。投稿は、内容を人が確認してから行う。
