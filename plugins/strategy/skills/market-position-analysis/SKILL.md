# 市場・競合・自社の整理（3C 分析 → 訴求設計）

フレームを埋めることをゴールにせず、**広告・SNS の訴求軸・媒体選定・クリエイティブ企画に直接接続できる粒度**で 3C を実施する。見つけたいのは「顧客が求めていて、競合が満たせておらず、自社なら応えられること」（KSF）。

## 最初に確定すること

- **対象企業/商材、目的**（顕在リード獲得 / 認知拡大 / ブランディング 等。何を決めるための分析か）、**エリア・対象市場**。分かれば KGI/予算感と既知の差別化ポイントも。
- ブランドナレッジ（brand-knowledge-from-url の出力）があれば先に読み、確認を省略する。
- Web 調査で解決できることは先に調べ、分からないときだけ質問する。調べても分からない前提は「仮定（Assumption）」と書いて進める。
- 読み手は広告の専門用語が分からない人（店舗のオーナー・広報担当・経営者）を既定にする。

## 手順

1. **情報収集。** 公式サイト（事業内容・料金・実績）、競合公式サイト（主要 3〜5 社の料金・訴求・強み）、業界団体・統計（市場規模・成長率）、Web 検索（シェア・競合比較・顧客アンケート）、ニュース・プレスリリースから集める。統計は「国 → 自治体 → エリア → 個店」の 4 段階でマクロからミクロへ積む。
2. **Customer（顧客）。**
   - 市場・対象の規模と属性（デモグラ・サイコグラ）を押さえる。
   - 顧客を **2〜3 ペルソナ**に分け、それぞれ属性・状況 / 悩み・不安 / 検討トリガー / KBF 上位 3〜5 を書く。
   - ペルソナ共通の KBF（購入の決め手）を 5〜7 個挙げ、重要な順に並べる。可能ならアンケート等の数値で裏付ける。
   - 検討プロセス（認知 → 興味 → 情報収集 → 比較 → 決定 → 利用 → 継続/紹介）の各段階で、情報チャネル・不安・離脱要因を特定する。
3. **Competitor（競合）。**
   - 「直接競合」だけでなく 5 階層で見る: ①直接競合 ②EC 競合 ③チャネル代替 ④顧客側プラットフォーム ⑤個人発信者（コンテンツ競合）。階層ごとに、自社にとっての意味を 1 行で書く。
   - 2〜3 軸の競合マップを作る（軸の例: 価格帯 × サービス品質 / 大手 × 地域密着 / 低価格訴求 × 信頼訴求）。
   - 主要競合 3〜5 社のポジショニング・主要訴求・料金体系・強み弱み・LP 構造を調べる。広告クリエイティブの傾向は、広告ライブラリを人が開いて記録した内容か、広告データを API・MCP で提供する商用サービスの値を使う。
   - 誰も応えていない空白（Whitespace）を**番号付きで** 5〜7 個挙げる（手順 5 で 1 つずつ採否を判断するため）。
4. **Company（自社）。**
   - 強みを 4 レイヤーで洗い出す: サービス力（提供価値・品質・独自機能）/ オペレーション力（スピード・柔軟性・内製比率）/ ブランド・信頼（歴史・実績・認定）/ 集客・データ（既存顧客数・LTV・紹介率）。
   - 既存の訴求資産（キャッチコピー・顧客の声・事例・写真や動画）を棚卸しする。
   - 依頼が SWOT のときは、手順 2〜4 で出た事実を SWOT（強み/弱み＝自社内部、機会/脅威＝外部環境）に並べ直す。新しい調査はせず、根拠の無い項目を足さない。クロス SWOT（強み×機会＝伸ばす一手、弱み×脅威＝守る一手）まで出すと KSF の候補になる。
5. **KSF（勝つ条件）を 3〜5 個に絞る。** 「経営課題への直結度 × Whitespace の大きさ × 自社アセット適合」の 3 つを満たす候補を優先し、1〜2 個しか満たさない候補は「後回し/捨てる」として理由つきで書く。各候補に定量 KPI を仮置きする。
6. **ポジショニング。** 競合マップに自社を置き、差別化を 1 行で書く。形式: 「◯◯（競合 A）と◯◯（競合 B）の中間で、◯◯という独自価値を提供」。
7. **WHO → WHAT → WHY → HOW の訴求設計。**
   - WHO: 主要ペルソナを 1〜3 個に絞り、広告配信のオーディエンス設計に使える粒度で書く。
   - WHAT: WHO の KBF と自社の強みが交差するメッセージを複数挙げる（訴求軸: 機能／ストーリー／比較／社会的証明／権威／限定性／共感・問題提起／ユーザー体験）。
   - WHY: なぜ今まで利用していなかったか（障壁: 情報不足／不安／満足してた／諦め）と、なぜ今伝えるのか。
   - HOW: クリエイティブ形式・配信媒体候補（絞り込みは media-selection）・LP の形式。
8. **レポートにまとめる。** [references/report-template.md](references/report-template.md) の構成で Markdown ファイルに保存し、保存先を伝える。

## 守ること

- **すべての表・数値に出典（ソース × 使ったデータ × 公表日 × URL）を付ける。** 出典に辿れない数字は使わず「未取得」と書く。
- **インタビューをしていない顧客の声を書かない。** 公開されている口コミ・アンケートは出典を付けて引用する。
- **事実と仮説を混ぜない。** 競合の強み・弱みは公開情報で確かめた事実だけを書き、推測には「仮説」と印を付ける。
- 広告ライブラリなどの SNS・広告の画面を自動で集めない（各社の規約が禁じている）。
- 空白（Whitespace）の大きさだけで訴求を決めない。競合がいないが需要も無い領域を選びやすい。

## 出力の型

- 冒頭は「一言でいうと」（勝つ条件・差別化の 1 行・最初に試す訴求・媒体の方向）。
- 各 C は Summary 1 段落で締め、最後に「誰に・何を・なぜ・どう」を 1 つの表にまとめる。
- 末尾に「データの限界と注意点」と「情報ソース」の表を必ず置く。

## フォールバック先

- 統計が国レベルしか見つからない / 競合のサイトや広告が調べられない: 取れた範囲で書き、欠けた項目を「未取得」として「データの限界」に書く。推計で埋めない。競合の広告は、広告ライブラリの検索 URL と空欄の記録表を作り、人に記録を頼む。
- 顧客の声が手元に無い: 公開の口コミを出典つきで使う。実在の顧客に話を聞けるなら single-customer-deep-dive へ。
- 利用者に質問できない（サブエージェントとして実行）: 仮定を明記して最後まで進め、仮定の一覧を冒頭に置く。
