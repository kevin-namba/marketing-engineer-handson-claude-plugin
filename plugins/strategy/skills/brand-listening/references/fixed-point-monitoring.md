# 定点監視の共通の仕組み

定点監視は、決めた対象を決めた間隔で同じ方法で集め、前回との差分だけを知らせる仕組み。定期実行に載せるとき、前回の値の置き場を決めるときに読む。

人が毎朝対象を開いて前回との違いを自分で比べる形（pull 型）から、仕組みが比べて差分だけを届ける形（push 型）に変える。流れは「前回の値を読む → 収集 → 差分の抽出 → 重要度の判定 → 定点レポート → 通知 → 次回のために保存」。

## 3 つのルール

- **履歴を残す。** AI は前回の作業の中身を覚えていない。前回の値は、作業のたびに消えない場所（案件のフォルダ、共有ドライブ、記録シート）に日付を付けて保存する。
- **見る項目を固定する。** 見なかった項目は「今回は対象外」、開けなかった項目は「未取得」と分けて書く。何も書かずに省くと、「変化が無かった」のか「見ていない」のか区別できない。
- **取得経路を揃える。** 取り方が変わると値の意味が変わる。前回と同じ取り方で取り、経路の違う値どうしで差分を出さない。

## 定期実行に載せる前に

- **通知先を決めてから載せる。** 通知の出ない自動実行は、何がいつ動いたか誰も知らないままになる。
- **数えるのはコード。** 件数・評点の平均・前回比は、コード（スクリプトや表計算）で数える。生成 AI に任せるのは、本文の要約・トーンの判定・対応の下書きまで。
- 定点で毎回見るのは数値表まで。本文まで読むのは新着（差分）だけにする。

## RSS で取れるもの

定点監視の材料で、いちばん安く安定して使えるのが RSS。既読の記事 ID（または URL）を外部に保存し、新着だけを次の処理に渡す。

| 取れるもの | 用途 | 備考 |
|---|---|---|
| ニュースサイト・企業のお知らせ・ブログ・note・Podcast | 業界ニュース、競合の PR、業界人の発信 | フィードの URL はサイトごとに違う。多くはページの head に自動検出用のリンクがある |
| YouTube のチャンネル | 競合チャンネルの新着動画 | チャンネル単位のフィードがある |
| Google トレンド（急上昇ワード） | 検索需要の立ち上がり | `https://trends.google.com/trending/rss?geo=JP`（執筆時点） |
| Google アラート・GitHub のリリース | ブランド名の言及、使っているツールの更新 | アラートは配信先に RSS を選べる（既定はメール） |
