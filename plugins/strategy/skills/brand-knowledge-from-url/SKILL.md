# URL からブランドナレッジを作る

サイトを読んで、そのブランドが「何者か」を短くまとめる。できあがったものは、以降の企画・執筆・分析で毎回の前提として使い回す。**推測ではなく、サイトに書いてあることだけ**で作る。

## 前提

- 入力は会社・サービスのサイト URL 1 つ。実行するのは最初の 1 回で、事業の内容が変わったときだけ作り直す。
- この Skill が作るのはブランドナレッジ（何者か）だけ。カスタム指示（AI にどう動いてほしいか）は別のファイルに分ける。更新の頻度も書く人も違う。

## 手順

1. **トップページを読む。** サイトが最も打ち出している事業と価値を最初に押さえる。
2. **主要な下層ページを読む。** 会社概要・サービス（商品）・料金・事例・よくある質問など。ナビゲーションやフッターから辿れるものを優先する（目安は 5〜10 ページ）。
3. **4 項目をそれぞれ 1 文で書く。**

   | 項目 | 書くこと |
   |---|---|
   | 事業 | 誰に、何を売っているか |
   | 主要ターゲット | 主に想定している顧客像（属性・利用シーン） |
   | 提供価値・強み | 顧客がこのブランドを選ぶ理由として、サイトが打ち出しているもの |
   | トンマナ | サイトの文章から読み取れる話し方やデザインや配色など |

4. **あわせて次の 3 つを整理する。** 収益モデル（何にお金を払ってもらうか）/ 購買までの導線（問い合わせ・予約・購入がどこで起きるか）/ いま使っている集客チャネルと、そこで何を訴求しているか。
5. **事実と推測・所見を分ける。** 確認できなかった項目は空欄のまま「確認できなかった項目」に並べ、読んでいて気づいた課題は「所見」に分ける。

## 守ること

- **事実だけを書く。** 「〜が弱い」「〜すべき」といった課題・所見・提案は、別の節（所見）に分ける。前提に混ざると、以降の作業がその評価を事実として扱う。
- **注記を混ぜない。** 「【推定】〜」「おそらく〜」は書かない。サイトから確認できない項目は空欄にして、「確認できなかった」と別に書く。
- **数字・実績・資格は、サイトに書かれている表現のまま写す。** 丸めたり言い換えたりしない。載っていたページの URL を添える。
- サイト以外（口コミ・ニュース・SNS）の情報は混ぜない。

## 出力の型

`brand-knowledge.md` として保存し、保存先を利用者に伝える。

```markdown
# ブランドナレッジ: [ブランド名]
作成日: YYYY-MM-DD / 元にしたサイト: [URL]

## 4 項目
- 事業: 
- 主要ターゲット: 
- 提供価値・強み: 
- トンマナ: 

## 収益モデル・導線・集客チャネル

## サイトに書かれていた数字・実績・資格（表記のまま）
| 内容 | 表記 | 載っていたページ |
|---|---|---|

## 確認できなかった項目

## 所見（ブランドナレッジには含めない）

## 読んだページ（URL と読んだ日）
```

以降の作業に前提として渡すのは「サイトに書かれていた数字」まで。「確認できなかった項目」と「所見」は渡さない。

## フォールバック先

- ページが取得できない・ログインが要る: 読めたページだけで書き、読めなかった URL を「確認できなかった項目」に並べる。必要なら利用者に該当箇所の文面かスクリーンショットを頼む。
- サイトが無い・情報が少ない: 書ける項目だけ書き、残りは空欄にする。利用者に会社案内・提案資料の持ち込みを頼むか、4 項目を質問して埋め、出どころを「利用者の回答（日付）」と書く。
