# チャネルルーティング（情報収集のツールを目的ごとに決める）

情報の集め方を AI に任せきりにすると、作業のたびに使うツールが変わる。前回は API から、今回は公開ページから数字を取っていたら、値が変わったときに事業が動いたのか取り方が変わったのかを区別できない。この Skill は「何を調べるときに何を最初に使い、使えなければ何に切り替えるか」を表で固定する。

## 前提

- 表のツール名は一般的な呼び方で書いてある。自分の環境のツール名に置き換えて使い、置き換えた表を案件のフォルダに保存して SSOT にする。
- この Skill が決めるのは「どう調べるか」。何を調べるかは、それぞれの分析の Skill が決める。

## チャネルルーティング表

| 目的 | 第一手 | バックアップ |
|---|---|---|
| テキスト情報の検索（事例・ニュース・人物） | Web 検索ツール | 言い換え/サジェスト → site: 検索 → 英語圏展開 |
| 特定ページの取得（静的） | ページ取得ツール（WebFetch 等） | JS レンダリングしてからの取得（本文が JavaScript で描画されるページのとき）。403 や bot 対策で拒否されたら回避せず「未取得」とし、利用者に本文か画面写しを頼む |
| 動的一覧・ページネーションのクロール | JS レンダリングしてからの取得（リンクが HTML に出ていれば全件取れる） | ブラウザ実査（Playwright MCP 等。**アクセス先は案件のサイトと、登録した競合の公式サイトに限る**。規約や robots.txt が自動取得を禁じているサイトと、Meta・Instagram・TikTok・X・YouTube・Google の検索結果は対象外） |
| SNS の実数・実在確認（フォロワー・再生数） | **Instagram / TikTok は人が画面で確認した値か公式 API の値だけ**（自社アカウントのインサイト、Instagram の Business Discovery API）。X は公式 API | ユーザーに画面の確認・スクショ提供を依頼する。取れなければ「未取得」。**ログインが要る数字は取れない** |
| 要ログイン SaaS の取得 | **取らない**（ログインを代行しない・認証を回避しない） | 管理画面のエクスポート（CSV）／スクショの持ち込みを依頼する |
| 動画広告・成果が出ているクリエイティブ | 広告ライブラリを人が開いて記録する（判定のしかたは第 7 章）か、広告データを API / MCP で提供する商用サービス（推定値は推定と明記） | Google 広告の透明性センター・TikTok Creative Center（どちらも人が開いて記録） |
| 定点巡回（RSS/フィード） | ページ取得ツール、またはフィードの読み取り（Python の feedparser 等） | 取れなければ「未取得」（403 を UA の変更などで回避しない）。フィードの URL が変わっていないかを確かめる |
| 検索順位・アクセス・広告の実績（Search Console / GA4 / 各媒体） | Search Console・GA4・広告媒体の API / MCP（連携していれば）。**これが唯一の経路** | 取れなければ「連携が未設定」と報告する。**Web 側で代替しない**（公開ページの数字は別のものになる） |
| YouTube の公開データ | YouTube Data API（API キーがあれば）。チャンネルの新着は RSS | 自社チャンネルは YouTube Studio の CSV 書き出し、他社は人が画面で確認した記録。動画ページを自動で開いて集めない |
| 社内情報（ドキュメント・ドライブ） | ドキュメント基盤・ドライブのコネクタ / MCP（**読み取りのみ**） | ユーザーにファイルの持ち込み（チャット添付）を依頼する。Web 側で代替しない |

## 手順

1. **目的を表の行に当てはめる。** 調べたいことを 1 行ずつ書き、表のどの行に当たるかを決める。
2. **使う手段と、止める条件を宣言する。** 例: 「事例は Web 検索で 7 クエリまで、上位 15 件。2 クエリ続けて新しい情報が無ければ止める」。一覧やメタ情報で広く見て、本命だけ詳しく読む。
3. **第一手で取る。** 取れなければ表のバックアップへ順に進み、取れた時点で止める。表に無い回避策を作らない。
4. **出典を付けて記録する。** 実際の URL と取得日に、信頼度（一次情報 = 当事者の発表・公式 API・人が画面で確認した数字 / 二次情報 = まとめ記事・支援会社の事例発表 / 推定 = ツールの推定値・検索結果の抜粋から読んだ値）を付ける。
5. **見た範囲と見ていない範囲を書く。** 打ち切ったときは、どこまで見たか・何を見ていないか・次に調べる価値があるものを残す。

## 守ること

- 取れなかったものは「未取得」と書く。ログインの壁・bot 対策・リンク切れで取れなかったものを「存在しない」と断定しない。
- ログインを代行しない・認証を回避しない。Meta・Instagram・TikTok・X の画面を自動で集めない（各社の規約が禁じている）。
- 403・CAPTCHA・bot 対策で拒否されたページを、UA の変更やヘッドレスブラウザで取り直さない。
- 下の表に無いサイトを自動で読むときは、先に利用規約と robots.txt を読み、結果を表に足す。
- 定点で取る数字は、前回と同じ経路で取る。経路の違う値どうしで差分を出さない。
- まとめサイトの数値は、一次情報（公式ページ）で確かめてから採用する。支援会社と事業会社で数字が食い違えば、事業会社（当事者）の発表を優先する。
- 日本のローカルな情報は、地名・年度（西暦と和暦）・媒体名をクエリに入れる。

## 自動で読んでよい面・読めない面（各社の利用規約と robots.txt を確認した結果。2026 年 10 月時点）

| 面 | 自動で読めるか | 根拠 |
|---|---|---|
| Google の検索結果ページ | 読めない | robots.txt が `/search` を禁止。利用規約が robots.txt に反する自動アクセスを禁止 |
| YouTube の画面 | 読めない（YouTube Data API と RSS は可） | 利用規約がロボット・スクレーパでのアクセスを禁止 |
| Instagram・TikTok・X・Meta の広告ライブラリ | 読めない | 各社の利用規約が自動化した手段での取得を禁止 |
| 食べログ | 読めない | 利用規約が営利目的での利用・アクセスと、口コミの無断利用を禁止 |
| ホットペッパー グルメ / Beauty | 読めない | グルメは利用規約が商業目的での利用を禁止。グルメ・Beauty とも、承認した以外の方法での利用を禁止 |
| じゃらん net | 読めない | 利用規約が承認した以外の方法での利用を禁止 |
| Indeed | 読めない | 求職者としての利用は、個人的・非商業的な求職の目的に限られる |
| Google マップ（検索結果・店舗のページ） | 少量なら読める | robots.txt が `/maps/search/` と `/maps/place/` を許可。マップの追加規約が禁じるのは大量のダウンロードと一括フィードの作成 |
| Yahoo!リアルタイム検索 | 少量なら読める | robots.txt に禁止の指定が無く、LINEヤフー共通利用規約に自動取得を名指しで禁じる条項が無い（BOT による不正な操作と、予定された利用態様を超える複製は禁止） |
| Google トレンドの RSS・各サイトの RSS | 読める | 配信用に提供されているフィード |

- 「少量なら読める」面は、1 回の件数を区切り、検索の間を空け、CAPTCHA が出たら中断する。本文を丸ごと保存・転載しない。
- 「読めない」面の数字は、自社（支援先）の管理画面の書き出し・公式 API・人が画面で確認した記録から取る。
- 楽天トラベル・ぐるなび・Retty・一休は規約を確認できていない。確認するまで自動では読まない。

## 出力の型

調査の成果物の末尾に、次の調査ログを付ける。

```markdown
## 調査ログ
- 目的と、使った経路: [表のどの行か / 第一手かバックアップか]
- 止める条件: [件数・クエリの上限] / 実際: [  ]
- 見た範囲 / 見ていない範囲:
- 未取得: [何が・なぜ・どうすれば取れるか]

| 情報 | 信頼度（一次 / 二次 / 推定） | URL | 取得日 |
|---|---|---|---|
```

## フォールバック先

- API・MCP の連携が無い（検索順位・アクセス・広告の実績）: 「連携が未設定」と書き、管理画面から出す CSV の種類を伝える。公開ページの数字で代替しない。
- 利用者に頼めない・返事が無い: 「未取得」と書いて先へ進み、成果物の末尾に取る方法を残す。
- 表に当てはまる行が無い: その場で手段を決めず、利用者に確かめて表に行を足す。
