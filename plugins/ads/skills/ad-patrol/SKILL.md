# 巡回

決まったルールどおりに「止める・減らす・通知する」定期実行。ルールに当てはまるかどうかは、AI Agent が考えず、
同梱のスクリプトが判定する。AI Agent が行うのは、実績を取得してスクリプトに渡し、返ってきた操作をツールで実行し、
結果を通知することだけ。

## 前提

- 確認画面なしで動かす想定（Claude Code のルーティン）。人が操作を確かめられるのは、**ルールを承認するとき**だけ
- 通知・停止・日予算の減額・複製（必ず停止状態で作る）は、即時に自動で行う
- 日予算の増額と配信の開始は、対象（`target.ids`）と上限（`budget_max`）を書いたルールを人が 1 回承認し、
  `approved` を書く。`approved` の無いルールと、上限を超える操作は「提案する」に入る

## 同梱するファイル

- `rules.json`: ルール（条件と操作の組）。同梱のものは例で、`enabled` を false にしてある。自分の案件の値に書き換えて使う
- `scripts/judge.py`: 判定のスクリプト。ルールと実績を受け取り、「実行する / 提案する / 見送る」に分けて返す。標準ライブラリだけで動く
- `references/rule-format.md`: ルールと実績のファイルの書式、スクリプトの結果の読み方

## 手順

1. 直近の実績を読み取りのツールで取得し、ファイル（`metrics.json`）に保存する。ルールの `window_days` と
   `target.level` に合う消化額・表示回数・クリック数・成果の件数と、現在の日予算・配信の状態を取る。
   **媒体が返した値をそのまま書き、単位は `units` で指定する**。取れなかった項目は `null` にする（0 にしない）
2. `scripts/judge.py` に `rules.json` と実績のファイルを渡して実行する

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/skills/ad-patrol/scripts/judge.py" judge \
     --rules "${CLAUDE_PLUGIN_ROOT}/skills/ad-patrol/rules.json" \
     --metrics metrics.json \
     --log patrol-log.jsonl
   ```

   案件ごとにルールを持つときは、そのパスを `--rules` に渡す。`--log` は実行の記録で、待ち時間と 1 日の上限回数の確認に使う
3. 「実行する」に入った操作だけを、返された引数のままツールで実行する（`args.status` と `args.to_in_media_unit` を
   そのまま使う）。「通知する」の操作は、ツールを呼ばずに通知だけ行う。1 件ずつ実行し、失敗しても残りは続ける
4. 実行した操作・提案・見送りを、理由とともに実行の記録に追記し、ルールの通知先へ送る。**何も実行しなかった回も送る**

   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/skills/ad-patrol/scripts/judge.py" record \
     --log patrol-log.jsonl --rule "<ルールの名前>" --target-id "<対象の ID>" \
     --action "停止する" --result "実行した" --detail "<理由>"
   ```

   `--result` は「実行した / 失敗した / 提案した / 見送った」。実行の記録は、次の巡回と周回（`ad-review`）が読める場所に置く

## 守ること

- 判定を自分で行わない。スクリプトが返していない操作は実行しない
- 「提案する」に入った操作（ルールの範囲を超える増額・配信開始）は実行しない
- 巡回の実行中は `rules.json` と `scripts/judge.py` を書き換えない
- 実績が取れなかった媒体は判定しない（0 として渡さず、`"status": "未取得"` と理由を書く）
- 失敗した操作を自動でやり直さない。失敗を記録して通知し、次の巡回に任せる

## ルールを作る・変える（人が依頼したときだけ）

1. 目標 CPA と撤退ラインを `cpa-budget-plan` の表から読み、ルールを 1 件ずつ書く（書式は `references/rule-format.md`）。
   最低消化額（`min_spend`）は 0 のままにせず、予算の下限と上限（`budget_min` と `budget_max`）は両方とも書く
2. `python3 "${CLAUDE_PLUGIN_ROOT}/skills/ad-patrol/scripts/judge.py" check --rules rules.json` で検査する。
   媒体でできない操作を書いたルールは、読み込んだ時点でエラーになる
3. ルールの内容を 1 文ずつ日本語で見せ、人が確かめる。支出が増えるルールは、対象と上限を見せて確認を取り、`approved` を書く
4. `enabled` を true にする。定期実行に登録するプロンプトには「巡回の Skill を実行してください」とだけ書き、
   Skill・`rules.json`・実行の記録は、ルーティンが取得するリポジトリにコミットしておく

## 出力の型

```
【巡回】<案件名> YYYY-MM-DD HH:MM（実績: 直近 7 日 / 取得できた媒体: Meta / 未取得: Google = 認証エラー）
■ 実行した（1 件）
- 停止: 広告セット「カラー_全年齢」（ID …）/ ルール「CPA が目標の 2 倍を超えた広告セットを止める」/ 直近 7 日の CPA 10,000 円が 8,000 円より大きい
■ 提案（実行していない。1 件）
- 日予算を増やす: 広告セット「髪質改善_20-39歳」2,800 → 3,360 円 / 20% 増やすとルールの上限（3,000 円）を超えるため
■ 見送り（3 件）
- 最低消化額に届かない: 2 件 / 学習期間中: 1 件
```

## フォールバック先（判定できないとき）

- スクリプトがエラーを返した（`"status": "error"`、終了コード 1）: 何も実行せずにエラーの本文を通知する。ルールを自分で直して再実行しない
- Python を実行できない: 判定を自分で代わりに行わない。何も実行せず、実行できなかったことを通知する
- 書き込みのツールが無い媒体: 「実行の手段が無いため、人が管理画面で行ってください」と通知し、記録には「見送った」と残す
- 確認画面が出る環境で動かすとき: 停止・減額は確認なしで進め、増額と配信開始は確認画面を通す
