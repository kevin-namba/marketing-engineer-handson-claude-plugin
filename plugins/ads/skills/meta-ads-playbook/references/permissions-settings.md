# パーミッションの設定（広告運用）

パーミッションは、AI Agent がツールを使う前に人の許可を求めるかどうかを、ツールごとに決める Claude Code の設定。

## 線引き

| 操作 | 設定 | 理由 |
|---|---|---|
| 実績・一覧・キーワード候補の取得 | allow | 読むだけ |
| 停止状態での作成、素材のアップロード | allow | 広告費は動かない。間違えても管理画面で直せる |
| 配信の停止 | allow | 支出が減る向き。再開はいつでもできる |
| **配信開始（出稿）** | **ask** | 許可したその時点から広告費が使われる |
| **予算の変更** | **ask** | 許可したその時点から広告費の使われ方が変わる |
| 状態や予算を変えられる更新のツール、任意の書き込みを送れる汎用のツール | **ask** | 名前に「配信開始」「予算」が無くても、この 2 つができてしまう |

書き込みのたびに確認画面が出ると、人は中身を読まずに許可するようになる。確認の対象は 2 つに絞る。
パーミッションはツールの名前で確認の要否を決めるので、配信開始は作成とは別のツールに分ける。

## `settings.json` の書き方（概念例）

```json
{
  "permissions": {
    "allow": [
      "mcp__meta__ads_get_ad_accounts",
      "mcp__google_ads__search",
      "mcp__google_ads__list_accessible_customers",
      "mcp__meta__ads_create_*",
      "mcp__ads_writer__validate_*",
      "mcp__ads_writer__create_*",
      "mcp__ads_writer__pause_*",
      "mcp__ads_writer__upload_*"
    ],
    "ask": [
      "mcp__meta__ads_activate_entity",
      "mcp__meta__ads_update_entity",
      "mcp__meta__ads_boost_ig_post",
      "mcp__ads_writer__activate_*",
      "mcp__ads_writer__update_budget_*",
      "mcp__ads_writer__raw_write"
    ],
    "deny": ["mcp__tiktok__*"]
  }
}
```

サーバー名は、登録したときに付けた仮の名前。自分の環境の名前に置き換える。`meta` と `google_ads` は公式 MCP のツール名
（執筆時点。公式のツール一覧で確かめる）、`ads_writer` は API をラップするために自分で作った MCP サーバーの概念例。
`tiktok` は、作成したキャンペーンが停止状態になるかを公式で確かめるまで使わないので、サーバーごと deny にしている。

## つまずきやすい点

1. **ask への書き忘れ**: 書き忘れたツールは確認なしで実行される。ツールを足すたびに漏れが無いかを確かめる。
2. **読むツールしか無いから安全だと考える**: Google の公式 MCP は参照しかできないが、連携のときに与える権限は読み書き共通。
   公式 MCP のツールも自作のツールも、1 つのパーミッションの設定にまとめて書く。
3. **確認画面で「今後は確認しない」を選ぶ**: 配信開始と予算の変更のツールでは選ばない。自分で作ったツールには
   確認必須の印（`anthropic/requiresUserInteraction`）を付けておけば、allow に書かれていても毎回確認画面が出る。
4. **確認を迂回する経路**: ターミナル（Bash）と広告の認証情報を渡すと、API を直接呼べてしまう。認証情報はツールの側に置く。

## 定期実行での違い

| 手段 | 確認画面 |
|---|---|
| ルーティン（クラウドで動く定期実行） | 出ない。含めたコネクターのツールは書き込みも確認なしで実行される（`ad-patrol`） |
| Claude Code Desktop のスケジュールタスク（自分の PC で動く） | 出る。確認が必要なツールが呼ばれると、人が許可するまで実行が止まる（`ad-review` の周回） |
