# 運用ログ

提案 1 件を 1 行で持つ台帳。段階（提案 → 実行 → 答え合わせ → 次に生かす）が進むたびに、同じ行の欄を埋める。

## 列

| 列 | 書くこと |
|---|---|
| 提案日 | 提案した日付 |
| 対象 | 媒体、広告セットや広告の名前と ID（名前だけだと、複製した広告と区別できない） |
| 仮説 | なぜその変更で良くなると考えたか |
| 変える箇所 | 1 行に 1 箇所。変更前と変更後の値 |
| 見込む効果 | どの指標が、いつまでに、どこまで動くか（率だけでなく分子と分母の見込みも書く） |
| 状態 | 提案 / 実行済み / 見送り（断られた理由を人の言葉のまま添える） |
| 実行日 | 媒体に反映した日付（学習期間と答え合わせの起点になる） |
| 結果 | 判定待ち / 見込みどおり / 見込みに届かない / 判定できない。根拠の数字を添える |
| 再現できるか | できる / できない（季節の需要など）。できる行だけを、次の企画に渡す |

```yaml
# 運用ログの 1 行（例。温泉旅館）
提案日: 2026-09-22
対象: {媒体: Meta, 広告セット: 平日限定プラン_30-49歳, ID: "（広告セットの ID）"}
仮説: 冒頭の写真が 3 週続けて同じで、見慣れられてクリック率が下がっている
変える箇所: {項目: クリエイティブ, 変更前: 露天風呂の昼の写真, 変更後: 夕食の写真（下書き B 案）}
見込む効果: 実行から 7 日でクリック率を 0.9% から 1.2% へ（表示回数が同じ水準なら、クリックは週 180 回から 240 回へ）
状態: 実行済み
実行日: 2026-09-24
結果: 判定待ち（実行日から 7 日未満）
再現できるか: 未判定
```

- 提案日・対象・仮説・変える箇所・見込む効果は、あとから書き換えない。見込みに届かなかった行も消さない。
- 「判定できない」は、別の変更が重なった・巡回が止めた・対象が審査で止まったときに使い、理由を書く。
- 巡回（`ad-patrol`）が実行した操作は、巡回の実行の記録に残る。運用ログには書き写さない。

## 許可待ちの通知の型

配信開始と予算の変更のツールを呼ぶ前に送る。確認画面に出るのはツールの名前と引数だけなので、理由はここで伝える。

```
【許可待ち】平日限定プラン_30-49歳 の新しい広告の配信開始
- 何を: 夕食の写真の広告（下書き B 案）を停止状態で作成しました。この広告の配信を始めます。
- なぜ: 冒頭の写真が 3 週続けて同じで、クリック率が下がっています。
- 見込む効果: 実行から 7 日でクリック率を 0.9% から 1.2% へ。
- 予算: 変えません。古い広告は、許可のあとに停止します。
Claude Code Desktop の確認画面で、許可するか断るかを選んでください。
```

予算の変更では「何を」に、広告アカウント名・対象の名前と ID・変更前と変更後の額と通貨を書く。

## スケジュールタスクに登録するプロンプトの例

```
周回の Skill（ad-cycle）を実行してください。
- 案件: 温泉旅館 / 媒体: Meta 広告と Google 広告
- 運用ログ: 共有スプレッドシート「運用ログ」シート / 巡回の実行の記録: patrol-log.jsonl
- 通知先: 広告の通知チャンネル
```

スケジュールは、人が PC を開いている時間帯に置く（許可を待つあいだ実行が止まる）。Claude を Slack やメールとつなぎ、
許可を待っている操作があることに人が気づけるようにしておく。Skill はスケジュールタスクの作業フォルダにコミットしておく。
