# 周回

次に何を変えるかを提案し、実行し、答え合わせするまでを回す定期実行（例は週 1 回）。
この Skill は自分では判定もレポートの執筆もせず、手順の順番と運用ログの受け渡しだけを受け持つ
（提案は `weekly-ad-tuning`、レポートは `ad-weekly-report`、実行は `meta-ads-api`）。

## 前提

- **確認画面が出る環境で動かす**（Claude Code Desktop のスケジュールタスク）。人が行うのは、確認画面の許可だけ。
  パーミッションの設定は `${CLAUDE_PLUGIN_ROOT}/skills/meta-ads-api/references/permissions-settings.md`
- 段階をつなぐのが**運用ログ**（提案 1 件を 1 行で持つ台帳）。次の実行からも読める場所（共有のスプレッドシートなど）に置く。
  列と例は `references/operation-log.md`
- スケジュールタスクに登録するプロンプトには、案件ごとの値（運用ログの場所、対象の媒体、通知先）だけを書く

## 手順

1. **運用ログと巡回の実行の記録を読む**（実績より先に読む）。判定待ちの行、見送りになった行と理由、
   巡回（`ad-patrol`）が止めた対象を確かめる。運用ログがまだ無い（初回）ときは新しく作る
2. **直近 7 日とその前の 7 日の実績を、読み取りのツールだけで取得する**（取り方は `ad-weekly-report` に従う）
3. **答え合わせをする**。状態が「実行済み」で結果が「判定待ち」の行のうち、実行日から 7 日以上たったものを、
   見込む効果と実績で比べ、結果と「再現できるか」を埋める。7 日未満の行は「判定待ち」のままにする
4. **提案とレポートを作る**（`weekly-ad-tuning` と `ad-weekly-report`）。判定待ちの行がある広告セットと、
   巡回が止めた広告セットは対象から外す。過去に外れた仮説・断られた提案と同じ内容は出さない
5. **提案を 1 件 1 行で運用ログに追記する**（状態は「提案」。変える箇所は 1 行に 1 箇所。対象は ID も書く）
6. **追記した提案を実行する**（`meta-ads-api` の手順）。配信開始と予算の変更は、呼ぶ前に「何を・なぜ・見込む効果」を
   通知してから呼ぶ。断られたら、その行の状態を「見送り」にして理由を書く
7. **実行した行の状態と実行日を更新し、通知する**（結論の 3 行と、実行した変更・見送った変更の一覧）

## 守ること

- 確認画面で断られた操作を別の方法で実行しない
- 運用ログに書いていない変更を実行しない。実行していないものを「実行済み」にしない
- 過去の行は、状態・実行日・結果・再現できるかの欄以外を書き換えない
- 提案が無い回も通知する（「今回は触らない」と理由）
- 同じ提案を続けて許可しているなら、その条件と上限をルールにして巡回（`ad-patrol`）に任せる案を通知に書く

## 出力の型

```
【周回】<案件名> YYYY-MM-DD（実績: MM-DD〜MM-DD / 未取得の媒体: なし）
■ 結論（3 行）
■ 答え合わせ（今回埋めた行）
- 9/24 実行「平日限定プラン_30-49歳 の写真の差し替え」: 見込みどおり（クリック率 0.9% → 1.3%、クリック 182 → 251）。再現できる
■ 実行した変更（対象の ID、変更前 → 変更後）
■ 見送った変更（断られた理由）
■ 許可待ち / 人が管理画面で行う変更
■ 判定待ちのため触らなかった広告セット
```

## フォールバック先（取得できないとき）

- 運用ログが読めない: 提案を作らずに止まり、読めなかったことを通知する（前の周を知らないまま提案しない）
- 実績が取れない媒体: 「未取得」と理由を書き、取れた媒体の分で書き切る。その媒体の行は「判定待ち」のままにする
- 共有のスプレッドシートが使えない: 運用ログを作業フォルダのファイル（CSV か Markdown の表）で持つ
- 確認画面が出ない環境で呼ばれた: 配信開始と予算の変更は実行せず、状態を「提案」のままにして通知する
