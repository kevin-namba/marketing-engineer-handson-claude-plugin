# 計測の読み方と、改善の型

## 計測する 3 つの数字

適正な値は流入の種類で大きく変わるので、必ず流入の種類ごとに見る。目安は経験則で、絶対の基準ではない。

| 数字 | 目安 |
|---|---|
| ファーストビュー通過率（ファーストビューのすぐ下までスクロールした人の割合） | 検索広告 80〜90% / サイト訪問者への再表示広告 60〜80% / 年齢・性別などで絞った配信 30〜50% / 絞り込まない配信 20〜30% |
| 申し込みボタンのクリック率（ボタンまで届いた人のうち押した人の割合） | 5〜15% |
| 料金表・お客様の声・よくある質問への到達率 | 下のほうにあって 1 割しか届いていなければ、上に移す候補 |

## 読むときの注意

- ヒートマップは、申し込んだ人だけに絞って見る。A/B テストの最中は見ない（2 つの案の数字が混ざる）
- GA4 では、必要なイベント（`section_view` / `cta_click` / `form_start` / 最終 CV）が LP から送られていることが前提（lp-measurement-tags）
- GA4 の数字は実際より少なめに出る。人数ではなく、段階ごとの割合で比べる
- 媒体が報告する申し込みの数と GA4 の数は数え方が違う。突き合わせず、合計せず、並べて出すだけ
- 数字が確定するまで 24〜48 時間かかる。直近 2 日は除く
- 人数の少ない行は伏せられることがある。伏せられた行は 0 ではなく「未取得」

## 改善の 9 つの型（案が尽きたらここに戻る）

| 優先 | 型 | 効果 / 手間 |
|---|---|---|
| 1 | バナーとファーストビューのつながりを強くする | 効果大・手間小 |
| 1 | ファーストビューの主張を裏付ける（すぐ下に数字・グラフ・比較表） | 効果大・手間小 |
| 2 | 権威・実績を入れる | 効果大・手間大 |
| 2 | 比較・併用の提案を入れる | 効果大・手間大 |
| 3 | 画像を差し替える | 効果小・手間小 |
| 3 | 読まれている要素を上に移す | 効果小・手間小 |
| 3 | 申し込みボタンの文言を変える | 効果小・手間小 |
| 4 | お客様の声を入れる | 効果小・手間大 |
| 4 | 今申し込む理由を入れる | 効果小・手間大 |

どの型も、裏付けのある事実だけで作る（実在しない実績・声・限定を作らない）。

## マイクロ CV（申し込みが少なく、最終 CV では判定まで待てないとき）

最終的な成果の手前で必ず起きる行動で判定する。使えるのは、増えれば最終的な成果も増える行動だけ。

| サイトの種類 | マイクロ CV | 最終 CV |
|---|---|---|
| 通販サイト | カートへの追加 | 購入の完了 |
| フォーム一体型の LP | フォームの入力開始 | 申し込みの完了 |
| 事業者向け | 入力フォームの表示 | 問い合わせ |
| 店舗の紹介サイト | 地図のページの表示 | 来店 |

## テストの進め方

- 少なくとも 1 週間単位で回す（曜日によって来る人が違う）。新しい案が勝つのは 3 割程度が普通。負けた案も記録して次の仮説に進む
- 件数に余裕があれば中身も並べる（売上・客単価・キャンセル率・実際に来店した割合）。申し込みは増えたのにキャンセルも増えた案を勝ちにしない
- 定石も思い込みで決めない。ファーストビューの申し込みボタンは、高価でまだ知られていない商品では逆効果になることがある
