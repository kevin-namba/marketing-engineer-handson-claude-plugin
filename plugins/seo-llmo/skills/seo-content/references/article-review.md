# 記事のレビュー

> `seo-content` の SKILL.md「記事のレビュー」の節から読む。成果物は評価。修正を適用するのは利用者が頼んだときだけ。

## 1. 機械的な検査（先に回す）

記事を上から読み、該当した行を行番号つきで書き出す。書き出したものは確認候補で、該当行を読んで判定する。

| 項目 | 拾い方 |
|---|---|
| タイトルの数字と見出しの数 | 「5 選」「3 つの理由」などの数字が、見出しの数と合っているか |
| 見出しの階層の飛び | h2 の次に h4 が来るなど、1 段を超えて下がっていないか |
| 文体の混在 | です・ます と だ・である を数える。少ないほうが 1 割以上あれば混在 |
| 出どころの無い数字 | 単位つきの数字（%・円・件・倍 など）がある段落に、出どころの語（出典・調査・当社・時点・URL など）が無い |
| 未解決の印 | 【要取材】【要確認】が残っている |
| 出してはいけない名前 | 利用者から渡された名前（クライアントや取引先の実名）が出ている |

## 2. 競合と比べる観点

比べる相手は、実際に取得できたページだけ。競合の構成を写すことを修正案にしない。

| 観点 | 見ること | 既定の重大度 |
|---|---|---|
| 話題の網羅 | 上位の 8 割以上が触れている話題を落としていない | 推奨 |
| 独自の話題 | 上位に無い自社の一次情報がある | 推奨 |
| 数字と事例 | 競合と比べて、出典表示や事例の具体さが弱くない | 推奨 |
| 表・図・画像 | 比較や料金など、表にすべき情報が文章のままになっていない | 推奨 |
| ページの形 | 記事の形が検索結果の主流と合っている | 推奨 |
| 文字数 / 内部リンク / 次の行動 | 極端に少なくない / 関連ページへのリンクがある / 案内が本文とつながっている | 任意 |

## 3. 公開ブロッカーにする項目

誤りの影響が大きい話題（医療・金融・法律など）では 1 段上げる。事実の誤りは公開ブロッカー。

| 分類 | 公開ブロッカー |
|---|---|
| 体裁 | 見出しの階層の飛び / 表・リスト・引用の記法の崩れ |
| 文体 | です・ます と だ・である の混在 / 話し言葉（「〜んです」「〜ですよね」）が地の文に残っている |
| 整合性 | タイトルの「○選」「○つの理由」が見出しで回収されていない / タイトル・説明文・見出しの主張が一致していない |
| 信頼の表示 | 数字に出どころが無い / 取材メモにも出典にも無い数字がある |
| 表現と権利 | 出してはいけない実名 / 「必ず」「絶対」「No.1」など根拠の無い断定 / 他社比較に出典と確認日が無い / 引用の範囲と出どころが不明 / 【要取材】【要確認】が残っている |
| 自社の文脈 | 自社の強み・提携・実績と矛盾する記述 |

推奨: 対策キーワードがタイトル・h1・最初の段落にある / 書き手が誰か分かる / 公開日・更新日・データの取得日がある /
取材で得た事実を主役にした見出しが 1 つ以上ある。

## 判定

- 公開ブロッカーが 0 件 → そのまま公開できる（推奨の指摘は添える）
- 1 件以上で、節の単位で直せる → 修正後に公開できる
- 構成が検索意図と合っていない、一次情報が無い、タイトルと本文の不一致が全体に及ぶ → 構成から作り直す

各指摘に付ける: 該当行（行番号と引用）/ 競合の実例（どの URL が、どう書いているか）/ 修正案（1〜2 文）。
競合を 3 本取得できないときは取れた本数で比べ、本数を書く。0 本なら機械的な検査だけで判定し、競合比較は「未実施」と書く。
