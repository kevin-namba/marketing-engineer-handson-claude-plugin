# AI の回答での言及の定点計測

> `ai-search-optimization` の SKILL.md「AI の回答での言及の定点計測」の節から読む。

計測に使うのは、各社の API の「検索グラウンディング」（モデルが Web を検索してから答える機能）。仕様と項目名は執筆時点のもの。公式ドキュメントで確認し、確認できない項目は読まず「未取得」とする。
公式ドキュメント: Gemini https://ai.google.dev/gemini-api/docs/generate-content/google-search / OpenAI https://developers.openai.com/api/docs/guides/tools-web-search / Anthropic https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool

## 質問の定義

```yaml
brand_terms:          # 表記ゆれ（漢字・かな・英字・略称）は 1 行 1 件
  - 山の湯旅館
own_domains:
  - yamanoyu.example.jp
competitors:          # 5 社まで。数えるのは登録した表記だけ
  - A 旅館
queries:
  - id: q01
    type: 指名        # 指名 / おすすめ / 比較 / 地域・用途
    text: 山の湯旅館はどんな宿ですか
    added: 2026-07-01
```

- 質問は合計 10〜20 本。文言は、実際の問い合わせ・予約の電話・商談で聞かれた言い方から取る
- 登録した文言は 1 文字も変えない。足すときは新しい id を振って追記し、id を使い回さない。やめる質問も行は消さない
- 対話できない実行で定義が無いときは、計測せずに「質問が未登録」と返す（推測で質問を作って測らない）

## 計測の経路（上から順に試す。使った経路を記録に残す）

1. 言及の計測用の MCP ツール（つないである場合）
2. 各社の公式 API の検索グラウンディングに、質問をそのまま投げる。課金の前に本数（質問数 × エンジン数）と概算を見せて確認を取る
3. 利用者が各サービスの画面で質問を投げ、回答と引用元を貼る（API の結果と同じ表に入れず、経路ごとに表を分ける）
4. どれもできないエンジンは「未計測」と理由

## 1 サンプルの記録

1 つの質問を 1 つのエンジンに 1 回投げた結果が 1 サンプル。1 行 1 件の JSONL に追記で保存する（過去の行は書き換えない）。

| 項目 | 値 | 意味 |
|---|---|---|
| `engine` | `gemini` / `openai` / `anthropic` など | アプリ名ではなく API の提供元 |
| `query_id` / `query` | 定義ファイルの id / 文言 | 文言はそのまま |
| `mode` | `search` / `no_search` | 検索の機能を渡したか |
| `searched` | true / false / null | 検索が実行されたか。判定できないときは null |
| `queries_executed` | 文字列の配列 | モデルが実際に投げた検索語。語句のまま |
| `brand_mentioned` | true / false / null | 回答の全文にブランド語があるか |
| `citations` / `cited_own` | `[{url, title, domain}]` / true / false / null | 回答に付いた引用元と、自社ドメインが含まれるか |
| `error` | null / 文字列 | API のエラー。あれば未計測 |
| `model` / `measured_at` / `route` | 文字列 / 日時 / `api`・`manual` | API が返したモデル名、日時、経路 |

検索が実行されたかは、回答の本文ではなく、API の応答に含まれる記録で判定する（執筆時点）。

| エンジン | 検索が実行された印 |
|---|---|
| Gemini API | 応答のグラウンディングのメタデータに、検索語か参照元が入っている |
| OpenAI API | 応答の出力に、Web 検索の呼び出しの項目がある |
| Anthropic API | 応答に、Web 検索のツールの使用と、その結果のブロックがある |

印を読めないときは `searched` を null にし、「検索の判定不能」として件数を書く。推測で true / false を入れない。

## 集計（エンジンごとに分ける）

1. サンプルを 4 つに分ける: 未計測（`error` あり）/ 成立（`searched` が true）/ 不成立（検索なし）/ 検索の判定不能
2. 成立のサンプルだけで数える
   - 言及率 = 言及あり ÷（言及あり + 言及なし）。分母が 0 なら「無し（成立 0 件）」（0% にしない）
   - 自社ドメインの引用率 = 引用あり ÷（引用あり + 引用なし）。`cited_own` が null のサンプルは分母に入れない
3. 不成立のサンプルは、言及率に足さず「知識での言及率」として別に出す
4. 成立していて言及なしのサンプルは、質問 ID・モデルが投げた検索語・引用元のドメインを一覧にする

- 言及の判定は、ブランド語（表記ゆれのどれか 1 つ）が回答の全文に含まれるか。表記ゆれを判定の側で推測して広げない
- 月ごとの比較は、両方の月で測った質問 ID だけで行う
- 出力には但し書きを入れる: API で測った結果で、消費者向けアプリの回答と一致するとは限らない。回答は毎回変わりうる
