# 施策の一覧と効果測定

> `seo` の SKILL.md「SEO 改善の全工程」「週次の改善サイクル（SEO / AI 検索）」の節から読む。

施策の一覧は、次の実行から読める場所（共有のスプレッドシートなど）に置く。SSOT は一覧だけにし、報告と通知は一覧の行を引用する。

## 施策の一覧の欄

1 行 1 施策。過去の行は書き換えず、あとから埋めるのは status と「実施後」の欄だけ。

| 欄 | 書くこと |
|---|---|
| id | 振り直さない。行を消さない |
| title / target（url・queries） | 施策の題、対象のページとクエリ |
| stage | どの段の仕事か（段の判定の節の結果） |
| kind | 既存記事の改善 / 新しい記事 / テクニカルの修正 / AI の回答での言及 |
| finding | 所見。数字と出どころを書く。推測は書かない |
| impact / confidence / priority | 見込める効果と確からしさを 0〜10。priority は impact × confidence。手間は並べ替えの補助 |
| baseline（window・position・clicks・source） | 施策の前の数字。期間・値・出どころ。あとから書き換えない |
| failure_if | 何がどうなったら効果が無かったと判断するかを 1 文で。あとから書き換えない |
| status | 提案 / 未着手 / 下書き入稿済み / 実施済み / 完了 / 見送り（「未着手」は人が採用した行） |
| done_on（実施後） | 人が公開した日。効果測定日の起点 |
| readback_due / readbacks（実施後） | 効果測定日の並びと、1 回につき 1 件の記録（read_on・window・position・clicks_per_day・verdict） |
| pattern（実施後） | 判断が「採用する」の行だけ。効いた変更を 1 文で |
| 見送りの理由 | 見送った行だけ |

- 比べる期間の長さが回ごとに違うので、クリックは 1 日あたりに直して比べる。取得できなかった回を、効果を測った回に数えない
- 効果測定が終わっていないページに、変更を重ねない

## 効果を測る時期と判断

| 変更の種類 | 効果を測る時期 |
|---|---|
| 既存記事の改善 | 7・14・28・56 日後 |
| 新しい記事 | 14・28・56・90 日後 |
| テクニカルの修正 | 最初の 7 日は毎日、その後 28 日後 |
| AI の回答での言及 | 毎週（1 回の結果では判断しない） |

| 判断 | 選ぶとき | 次の周で起きること |
|---|---|---|
| 採用する | failure_if に当たらず、ベースラインより良くなったと言える | 行を「完了」にし、効いた変更を pattern に書く。同じ型が当てはまる他のページを「提案」の行として足す |
| 続けて様子を見る | まだ最後の効果測定日ではなく、どちらとも言えない | 次の効果測定日まで何もしない |
| 元に戻す | ベースラインより悪くなり、変更が原因だと見られる | 「元に戻す」を新しい行として提案する |
| 効果を確かめられない | どちらとも言えないまま最後の効果測定日を迎えた、または他の変更と重なって切り分けられない | 行を「完了」にするが、pattern は空のままにする |

最後の効果測定日には「続けて様子を見る」を選ばず、failure_if の文に照らして残りの 3 つから選ぶ。

## 流入が落ちたときの切り分け

原因を決めつける前に、関係の無い要因を上から順に外す。各段で「外せた / 外せない / 確かめられない」と根拠を書く。

| 段 | 外すもの |
|---|---|
| 1 | どのクエリ・ページで落ちたか（`seo-measurement` の「流入の分析」の節） |
| 2 | 季節性。前年の同じ期間とも比べる（取れなければ「未取得」） |
| 3 | 計測の変化。タグの付け替え・プロパティの変更・Search Console の集計の遅れ（直近 2〜3 日） |
| 4 | サイトの変更。テンプレートの変更やページの削除（`seo-technical` の「変更の見張り」の節、施策の一覧の実施日） |
| 5 | 外の要因。テレビや SNS による指名検索の増減・広告やキャンペーンの開始と終了（利用者への確認） |
| 残り | 説明できない下落だけを、順位の変動や競合の変化として調べる |
