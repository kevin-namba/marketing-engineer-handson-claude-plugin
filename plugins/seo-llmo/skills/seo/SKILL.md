# SEO（入口）

SEO の依頼はここから入る。通しの改善・サイト全体の監査・段の判定・週次の周回はこの Skill の節で進め、
個別の作業は分類（テクニカル / コンテンツ / 被リンク / ローカル / 計測）の Skill へ渡す。
手順は下の節に書いてある。**該当する節の手順で進める。**

| やりたいこと | 節 |
|---|---|
| 改善を、現状把握から効果測定まで通しで回す（1 周目） | 「SEO 改善の全工程」 |
| サイト全体を監査し、統合スコアとアクションプランを出す | 「サイト全体の SEO 監査」 |
| どこから手をつけるかを決める | 「どの段で詰まっているか」 |
| 2 周目以降の効果測定と、新しい候補の追加 | 「週次の改善サイクル（SEO / AI 検索）」 |

## SEO 改善の全工程

> **使う場面**: サイトの SEO 改善を、現状把握から効果測定まで工程ごとの節へ渡しながら回す。
> 「SEO を改善して」「検索流入を増やしたい」「順位が落ちたので立て直したい」で使う。

### オントロジー（出てくるモノと関係）
- サイト（サイト ID）→ ページ（正規の URL）。検索実績は「期間 × 検索語 × ページ」で持ち、確定 / 未確定 / 未取得を分ける
- 順位の記録は、追跡する語ごとに 1 日 1 行（実測 / 平均掲載順位 / 未取得）
- 施策（施策 ID）は所見から起こし、どの段の仕事かを持つ。決めた日に効果測定を起こす
- AI 検索の質問（質問 ID。文言は変えない）→ エンジンごとのサンプル → 回答 → 引用。
  答える段落が無かった検索語は、同じ施策の一覧に入れる
- 店舗のプロフィール（媒体側の ID）は、地点ごとの順位と口コミを持つ。返信は店舗が確認してから公開する

### 工程
1. 計測が入っているかを確かめる（入っていなければそこから）
2. **現状把握を省略しない**：初回と四半期の見直しではサイト全体の監査を行い、毎回、流入の分析と順位の基準値を先に取る
3. どの段で詰まっているかを判定する（段の判定の節）
4. 施策を一覧にし、効果 × 手間で並べる
5. **効果測定日を先に決める**
6. 実行（リライト / 新規 / テクニカル）→ 公開は人が押す
7. 実施日と効果測定日を施策の一覧に書く（以降の効果測定は週次の改善サイクルの節へ）

### 守ること
- 施策の実施日を記録する（後から因果を語るのに要る）
- 1 か月で成否を断定しない。ベースラインの無い施策を始めない
- 「順位が落ちた」依頼では、原因の切り分けを飛ばしてリライトに取りかからない

施策の一覧の欄、効果を測る時期と判断、流入が落ちたときの切り分けは `references/seo-improvement.md` にある。

## サイト全体の SEO 監査

> **使う場面**: サイト全体の SEO 監査の起点の節。URL を受け取り、描画・業種の見立て・クロールを
> 行ったうえで専門の担当へ委譲し、統合スコアとアクションプランを返す。
> 「SEO 監査をして」「サイト全体を診断して」「検索に弱い理由を洗い出して」で使う。
> ※1 ページだけの診断は `seo-technical` の「ページ診断」の節、順位だけ知りたい依頼は `seo-measurement` の「検索順位の計測」の節へ。

### 手順
1. トップページを描画し、業種（店舗 / EC / メディア / SaaS / 代理店）を見立てる
2. robots.txt を読んでから、上限ページ数までクロールする
3. 次の担当へ委譲する（どの担当も、自分が起点の節にはならない）
   - 常に: テクニカル / コンテンツ / 構造化データ / サイトマップ / 表示速度 / 見た目 / AI 検索対応 / 検索体験
   - 常に: Google の実測（CrUX・Search Console・GA4）と被リンク。連携が無ければ「未取得」で返る
   - 店舗のシグナルがあるとき: ローカル
   - ブログ・特集のシグナルがあるとき: トピッククラスタ
   - 商品ページのシグナルがあるとき: 商品ページ
   - 前回の控えがあるとき: 前回との差分
4. 各担当の所見を、固定の重みで 0〜100 の統合スコアにまとめる

### フォールバック先
- 連携が 1 つも無くても監査は成立させる。取れなかった項目は理由つきで「未取得」と書く
- 被リンクで参照ドメインの一覧が取れないときは、スコアを出さず「データ不足」と書く

### 出力
- 一言でいうと（3 行）/ 統合スコアと内訳 / Critical・High・Medium・Low の所見 / アクションプラン
- 各所見に、根拠（URL と実測値）と取得経路を付ける

業種のシグナル、クロールの上限、統合スコアの重み、テクニカルの点検項目、重大度の定義は `references/site-audit.md` にある。

## どの段で詰まっているか

> **使う場面**: SEO の仕事が 4 段（需要を見つける / 外側の裏づけ / 資産を整える / 事業と結ぶ）の
> どこで詰まっているかを判定し、その段の仕事だけを出す。
> 「SEO のどこから手をつければいい」「やることが多すぎて決められない」で使う。
> ※段が決まってから、監査の節や各分類の Skill へ渡す。

> Framework and prompts © Daniel Agrici, CC BY 4.0 — github.com/AgriciDaniel/flow

段の名前と考え方は、公開のフレームワーク FLOW（Find → Leverage → Optimize → Win）の要約・翻案による。
出力の冒頭にも上の出典表記をそのまま入れる。

### 手順
1. 4 つの問いに順に答える（はい / いいえ / 判定できない）。最初に「はい」にならなかった段で止める
   - Find: 誰がどんな言葉で探しているかを、実数と上位の顔ぶれで言えるか
   - Leverage: 自社サイトの外に、自分たちを裏づけるものがあるか
   - Optimize: 自社のページは、抜き出して引用できる形になっているか
   - Win: 流入が、予約や問い合わせにつながっているか
2. 止まった段を宣言し、**その段の施策だけ**を 3〜5 件並べる
   （渡す先: Find = `seo-content`・`seo-measurement` / Leverage = `seo-backlinks` /
   Optimize = 監査の節・`seo-technical`・`seo-content` / Win = `seo-content` の「検索体験の点検」の節・第 4 章の lp-improve）
3. 他の段の施策は「今回はやらない」と書いて残す

### 守ること
- 書き始める前に、どの検索面に向けるのかを明示する
- 出典に辿れない数値は、直すのではなく削る
- 可視性の指標だけを並べない（問い合わせや予約と対で評価する）
- 問いに答える材料が取れなければ「判定できない（未取得）」とし、「たぶん大丈夫」で「はい」にしない

## 週次の改善サイクル（SEO / AI 検索）

> **使う場面**: SEO と AI 検索の週次の改善サイクルを回す。施策の一覧を読み、効果測定日に達した行の
> 効果を測って判断を付け、言及を測り、新しい候補を一覧に足して通知する。
> 定期実行から呼ばれる。「毎週の効果測定を回して」「先月の施策の結果を確かめて」で使う。
> ※入稿・公開・サイトマップ送信はしない（採用された提案の実行は `seo-content` の「記事制作の全工程」の節へ）。
> ※新規案件の 1 周目は SEO 改善の全工程の節へ。

### 手順
1. 施策の一覧を読む（実績より先に読む）
2. 状態が「実施済み」で、効果測定日に達した行だけ実績を取得し、ベースラインと比べて
   効果測定の記録を足す（期間の終了日は取得日の 3 日前）
3. 判断を付ける。最後の効果測定日は failure_if に照らし、「続けて様子を見る」を選ばない
4. 登録済みのクエリで言及を測る（`ai-search-optimization` の「AI の回答での言及の定点計測」の節）
5. 新しい候補を「提案」の行として足す：採用した型の横展開 / 言及されなかった検索語 /
   月初は流入分析と順位計測の節の結果
6. 結論 3 行、効果を測った行と判断、判断が要る提案の一覧を通知する
   （「下書き入稿済み」のまま 7 日たった行も並べる）

### 守ること
- 入稿・公開・サイトマップ送信のツールを呼ばない（定期実行には確認する人がいない）
- 過去の行は、状態・実施日・効果測定の記録・再現できる型・見送りの理由の欄以外を書き換えない
- 最後の効果測定日が来ていない行と同じページには、新しい変更を提案しない
- 効果を測る行も提案も無い週も通知する（次の効果測定日を添える）

### 取得できないとき
- 施策の一覧が読めないときは、効果測定も提案もせずに止まり、読めなかったことを通知する
- Search Console のデータを取得できないときは判断を付けず、効果測定日を残して「未取得」と通知する
- 言及の計測ができなかったエンジンは「未計測」と書き、言及なしに数えない

施策の一覧の欄と判断の選び方は `references/seo-improvement.md` にある。

## 共通の規則

- **起点は 1 つにする。** 通しの依頼は「SEO 改善の全工程」、監査は「サイト全体の SEO 監査」の節から始め、
  各工程は分類の Skill の節へ渡す。起点の節が自分で監査や執筆を始めない
- **段の判定を飛ばさない。** 飛ばすと、テクニカルの指摘が数十件並んだ報告になる
- **取得できなかった数字は「未取得」と書く。** 0 で埋めない。推測値を実測のように書かない
- **「取得できるか」は呼んで確かめる。** 認証情報があることと、データを取得できることは別
- **外部に反映される操作（公開・CMS の更新・サイトマップ送信）は、内容を見せて人の確認を取る**

## 関連する Skill

- `seo-technical` … テクニカル / `seo-content` … コンテンツ / `seo-backlinks` … 被リンク / `seo-measurement` … 計測
