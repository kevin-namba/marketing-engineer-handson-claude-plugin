# SEO の計測

SEO の数字を取得し、判断の材料にする Skill。データの取得（検索実績・順位・表示速度）と、
その上の分析（どのキーワード・ページをテコ入れするか）を扱う。

節: 「検索実績の取得」/「流入の分析」/「検索順位の計測」/「表示速度の計測」

## 検索実績の取得

> **使う場面**: 検索の実績（クリック・表示回数・CTR・掲載順位）、URL の登録状況、サイトマップを取る。
> 「サーチコンソールのデータを取って」「クエリ別の実績」「この URL は登録されているか」で使う。
> ※どのキーワードをテコ入れするかの判断は流入の分析の節、実際の検索結果の順位は検索順位の計測の節。

### 手順
1. プロパティを一覧から選ぶ（手入力させない。形式の違いで 403 になる）
2. 期間・粒度（クエリ / ページ / 国 / デバイス）・件数の上限を先に決める（既定: 直近 28 日、終了日は 3 日前）
3. 取った値はそのまま渡す。**CTR は 0〜1 の生値**なので、表示する側で 1 回だけ % に直す
4. 取れなければ「連携が未設定」と対処法を返す（0 で埋めない）

### やらないこと
- 直近 2〜3 日の未確定値を評価に使わない
- サイトマップを送信しない。点検から送信と送信後の確認までは `seo-technical` の「サイトマップ」の節で行う
- 行数で切った合計を、サイト全体の合計にしない（全体の合計は軸を空にして取る）

取得経路の順、API の呼び出し方、URL 検査で読む項目、取れないときの切り分けは `references/search-console-data.md` にある。

## 流入の分析

> **使う場面**: 検索実績から、テコ入れすべきキーワードとページを特定する。
> 「流入分析をして」「CTR が低いキーワード」「リライト候補を探して」で使う。
> ※データの取得は検索実績の取得の節。この節はその上の判断。

### 手順
1. 期間を 2 つ取る（今回と前回。季節性があれば前年同期も）
2. 3 つの群に分ける：**あと少しで上位**（掲載順位 11〜20 位）/
   **表示は多いが押されていない**（10 位以内で CTR が低い）/ **下がっている**（前回から 3 位以上落ちた）
3. 群ごとに打ち手を分ける（本文を足す / タイトルと説明を直す / 原因を切り分ける）
4. 直す前に、クリック上位 1 割の語を「守るリスト」に控える

### 守ること
- 候補を選ぶ条件は数値で固定し、その場で基準を考えない。各候補に根拠の行（クエリ・ページ・順位・表示回数・CTR・クリック）を付ける
- 件数の少ないキーワードの CTR を率で断定しない（分母を一緒に書く）
- 順位の変化と施策の実施日を並べてから因果を語る。材料が無ければ「原因は未特定」と書く

## 検索順位の計測

> **使う場面**: 登録済みのキーワードについて、自社サイトの Google 検索順位を実際の検索結果で
> 測り、日ごとに記録して前回と比べる。「順位を測って」「何位か確認して」
> 「先週から順位はどう変わった」で使う。
> ※検索回数や入札単価はキーワード実数値の Skill（第 5 章。順位の代わりには使わない）。
> 流入の分析や改善候補は流入の分析の節へ。

### 手順
1. 計測対象のキーワードとサイトを、登録済みの一覧から読む（その場で作らない）
2. キーワードごとに実際の検索結果での順位を取る。経路は上から順に試す
   - 順位計測の MCP ツール、または検索結果を API で提供する商用サービス（つないである場合）
   - 利用者がログインしていないブラウザで検索し、順位と URL を記録した表（検索した日時と地域を添えてもらう）
   - 1 ページ目に無いときだけ 2 ページ目を見る。2 ページ目にも無ければ「圏外」
3. **Google の検索結果ページをエージェントが自動で開いて集めない**（Google は robots.txt で検索結果ページへの
   自動アクセスを禁じている）。上の経路で取れないキーワードはフォールバック先へ回す
4. 1 キーワード 1 日 1 行で記録する（`date,keyword,domain,rank,url,source,note`）。記録には必ず取得経路を入れる
   （実測（ツール名 / 人の記録）/ Search Console の平均掲載順位 / 未取得）

### フォールバック先
- 実測できなかったキーワードは、Search Console の平均掲載順位を入れる。
  経路の列を「平均掲載順位」にし、実測の値と断りなく混ぜない
- それも取れなければ「未取得」。0 位や 100 位で埋めない

### 出力
- キーワード / 今回の順位 / 前回の順位 / 変化 / 取得経路 の表
- 平均順位は順位の付いたキーワードだけで出し、圏外の件数を別に書く
- 期間の中で取得経路が変わったキーワードには、その旨を注記する（経路が違う値どうしは比べない）

## 表示速度の計測

> **使う場面**: ページの表示速度を、検査室の計測と実利用者の計測の両方で取る。
> 「表示速度を測って」「Core Web Vitals」「LCP が悪い」で使う。
> ※直す順番の判断は `seo-technical`。

### 手順
1. 1 回の実行で、検査室の値と実利用者の値を両方取る
2. **両者を混ぜない**。検査室の値は原因を探す用、実利用者の値は判定用
3. 実利用者の値が返らないページ（訪問が少ない）は「未取得」と書く
4. 推移を見るときは週単位の履歴を使う（単発の値で良し悪しを言わない）

**やらないこと**: 検査室の点数をクライアントへの報告の主役にしない

取得経路の順、判定のしきい値、API の呼び出し方は `references/pagespeed-and-crux.md` にある。

## 共通の規則

- **検索の実績は「検索実績の取得」の節の経路 1 本で取る。** 流入の分析も、順位のフォールバックも、
  監査で使う実測もここを通す。経路が 2 本になると、単位と期間の解釈がずれる
- **単位は取得経路ごとに確定させる。** CTR が 0〜1 の比率なのかパーセントなのかを、値の大小から推測しない
- **順位に見えて順位ではない数字を混ぜない。** 平均掲載順位・キーワードプランナーの値は、実際の検索結果の順位の代わりにならない
- **取得できなかった数字は「未取得」と書く。** 小規模サイトで実利用者の値が無いのは正常で、0 や「遅い」ではない
- **サイトマップの送信・インデックス登録の依頼は外部への反映。** この Skill では行わない（送信は `seo-technical` の「サイトマップ」の節で、人の確認を通して行う）

## 関連する Skill

- `seo` … 入口（改善の全工程・サイト全体の監査・段の判定・週次の周回）
- `seo-technical` … テクニカル / `seo-backlinks` … 被リンク
- `seo-content` … コンテンツ（直し方の指示書は「記事のリライト指示書」の節）
- `ai-search-optimization` … AI の回答での可視性と言及の定点計測
- 検索ボリュームと CPC の実数値は第 5 章の plugin（`ads`）の `keyword-volume`
