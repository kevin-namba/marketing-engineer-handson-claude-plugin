# 被リンクの整理

> **使う場面**: 被リンク（他のサイトから自社サイトへ張られたリンク）の現状を、取れる範囲で集めて並べる。
> 「被リンクを調べて」「参照ドメイン」「リンクの差を見たい」で使う。

## 前提

- 被リンクの全体像は、商用のデータ API が無いと取れない。ここでは商用の API を契約していない前提で、
  **取れる範囲で出し、足りなければ点数を出さない**
- 無料の情報源が返すのは、その時点の状態だけ。**増減の推移は取れない**
- 店舗型のビジネスで見るべきなのは、リンクの数より、実際に関係のある組織（地域の観光協会・商工会・
  地域メディア・取引先など）からのリンクが揃っているかどうか

| 情報源 | 取れるもの | 確かさの扱い |
|---|---|---|
| リンク元のページを実際に開いて確かめる | 既知のリンクがいまも残っているか | 最も高い |
| 被リンクの API（Moz など） | 参照ドメインの一覧・アンカーテキスト・各社独自の指標 | 高い。ただし指標は各社の推定値 |
| Bing Webmaster Tools | Bing が把握しているリンクと、競合サイトとの比較 | 中程度。Bing のインデックスの範囲に限られる |
| Common Crawl のウェブグラフ | ドメイン単位の中心性の指標 | 低い。参照ドメインの一覧は返らない |

## 手順

1. **取得元ごとに取り、どの元から取った値かを行に残す**（指標 / 値 / 取得元 / 取得日）。
   経路は MCP ツール → 利用者が API・管理画面から出した結果 → 未取得 の順。
   Bing の件数は「Bing が把握している範囲」で、被リンクの総数として報告しない
2. **同じドメインの重複を除く。** `www` の有無・http と https・末尾のスラッシュの違いは同じものとして扱い、
   本数ではなく参照ドメインの数で数える
3. **リンク元が残っているかを実際に見に行く。** 既知のリンク元を 1 件ずつ取得し、3 つに分ける
   - 残っている: リンク先の URL・文言・rel（`nofollow`・`sponsored`・`ugc` があれば follow ではない）を書く
   - 見つからない: ブラウザで開いて確かめてから「消えた」と書く
   - 確認できない: SNS など JavaScript で描画されるページ、4xx・5xx、取得できなかったページ。「消えた」とは書かない
4. **取れた要因が少なければ、点数を出さず「データ不足」と書く。** 6 要因のうちデータのあるものが 4 つ以上なら
   点数を出し、4 つ未満なら「データ不足（6 要因中 n 要因）」として、取れた値だけを取得元と一緒に並べる
5. **リンクの差を出す。** 競合にはリンクしているのに自社にはしていないドメインの一覧。取れなければ「未取得」。
   店舗型なら、関係のある組織を利用者と一緒に書き出して突き合わせる。連絡・掲載依頼は人の仕事
6. **不自然なリンクの手掛かりを並べる。** 「事実」として並べる（どのドメインから、何本、どの文言で）。
   手動による対策の有無は、Search Console で利用者に確かめてもらう

要因・重み・確かさと計算式は `references/sources-and-confidence.md`、
アンカーテキストの目安・不自然なリンクの手掛かり・否認の条件は `references/link-quality-patterns.md` にある。

## 守ること

- **「返らない」を「0 件」と読み替えない。** Common Crawl が参照ドメインの一覧を返さないのは「被リンクが 0」ではない
- **取れなかった要因は 0 点にしない。** 計算から外し、残りの要因で重みを配り直す
- **目安の値を公式の基準のように書かない。** どこから危ないのかを Google は公表していない
- **否認の提案を先に出さない**（最後の手段）。「否認を推奨」とは書かず、根拠を並べて判断を人に任せる
- **推移を聞かれたら「推移の追跡には対応していない」と答える。** 今回の結果を基準日として残せば、次回から差分は出せる

## 出力

```yaml
site: yamanoyu.example.jp
checked_at: 2026-09-20
health_score: データ不足（6 要因中 3 要因）   # 4 要因に届かなければ点数を出さない
factors:
  - name: 参照ドメイン数
    value: 42
    source: 被リンクの API
  - name: 不自然なリンクの割合
    value: 未取得
    reason: スパムの指標を返す API キーが未設定
link_checks:               # 既知のリンクが残っているかを実際に開いて確かめた結果
  - from: https://kanko.example.jp/stay/
    status: 残っている
  - from: https://social.example.com/post/123
    status: 確認できない（JavaScript で描画されるページ）
link_gap:                  # 競合にはあり、自社には無いリンク元
  - https://onsen-guide.example.jp/
```

レポートにするときは、この前に「一言でいうと」を 3 行で置き、後ろに「未取得の項目と、何をすれば取れるか」を並べる。

## フォールバック先

- **情報源が 1 つも無い**: 利用者が知っているリンク元を聞き、実際に開いて確かめる。点数は出さず「データ不足」
- **Common Crawl しか無い**: ドメイン単位の指標だけを並べる。参照ドメインの一覧は「未取得」
- **商用のデータが必要な依頼**（大規模な競合比較・有害リンクの網羅的な検出）: 取れないと伝える。推定値で埋めない
