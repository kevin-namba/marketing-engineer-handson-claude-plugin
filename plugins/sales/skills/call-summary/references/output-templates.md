# 商談の後処理: 3 つの成果物のテンプレート

## 1. 社内サマリー

```markdown
## 商談サマリー: （企業名・正式名称）— YYYY-MM-DD
出席者: 先方 （氏名・役職）/ 当社 （氏名）｜種別: （初回ヒアリング / 提案 / 交渉 / 定例）｜所要時間: （分 / 不明）

### 主な論点
1. （話題）— （話した内容・決まったこと）
### 相手の優先事項
- （発言の引用を添える）
### 提案した内容と反応
- 提案: （プラン・金額・期間・開始時期。メモのとおり）/ 反応: （発言の引用）
### 出た反論・懸念
| 懸念 | こちらの回答 | 状態（解消 / 持ち帰り / 未回答） |
|---|---|---|
### 競合への言及
- （社名・比較の観点・先方の評価。無ければ「なし」）
### アクション
| 担当者（当社・先方） | アクション | 期日（YYYY-MM-DD / 期日未定） |
|---|---|---|
### 次のステップ
### 確認事項（メモから特定できなかったこと）
### 商談への影響（ここは解釈）
- （ステータスが変わりそうか・リスク・加速する要因）
```

## 2. 顧客向けフォローアップ

```plain text
件名: 本日のお打ち合わせのお礼と今後の進め方

（氏名）様

本日はお時間をいただきありがとうございました。

本日お話しした内容は次のとおりです。
- （要点）

当社からは、次の対応をいたします。
- （約束したこと）（期日）

（次のステップ。期日つき）

引き続きよろしくお願いいたします。
（署名）
```

プレーンテキストで書き、太字・見出しの記法を使わない。相手の取り組みは尊敬語、自社の行動は謙譲語。
確度・社内の懸念・競合の評価・値引きの余地は入れない。

## 3. ステータスの定義の例

CRM の更新案の書式は SKILL.md の例のとおり（根拠を書けない変更は案に入れない）。
自社の定義が無いときは次の例を使う（確度は一例。自社の実績から決める）。

| ステータス | 確度（一例） | 遷移条件（誰が見ても同じ答えになる事実） |
|---|---|---|
| 未接触 | 0% | リストに載った。接触前 |
| アポ獲得 | 10% | 商談の日程が確定した |
| 担当者検討 | 25% | 提案を提示し、先方社内で検討中 |
| 担当者合意 | 50% | 担当者が導入の意思を文面か口頭で表明した |
| 決裁者合意 | 90% | 決裁ラインの合意が取れた（稟議の通過など） |
| 締結 | 100% | 契約書に双方の署名が揃った |
| 保留・失注 | 0% | 先方が見送りを表明した、または人が失注と判断した（理由を選択式で残す） |
