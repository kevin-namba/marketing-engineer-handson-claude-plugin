# 商談の後処理

商談の後に人が手で書くのは、簡単なメモか文字起こしの貼り付けまで。そこから 3 つの成果物を分けて作る。

## 入力

ラフなメモ / 文字起こし（貼り付け・アップロード・資料置き場のテキスト）/ 口頭の説明。通話を自動で記録する経路は持たない。
CRM の現在の値を読めれば、更新案の「現在の値」に使う。商談ステータスの定義（遷移条件）が設定にあれば読む。
無ければ `references/output-templates.md` の例を使い、その旨を更新案に書く。

## 手順

1. **メモを構造化する。** 出席者（氏名と役職）/ 種別 / 日付 / 所要時間 / 論点。読み取れない項目は「不明」。
   会社名が略称なら、正式名称を確認するか CRM の企業名に合わせる。
2. **論点を抜く。** 決定事項、相手の優先事項、出た反論とこちらの回答（解消 / 持ち帰り / 未回答）、競合への言及（無ければ「なし」）、未解決の質問。
   誤変換と思われる箇所は直さず「（聞き取り不明）」と書く。
3. **アクションを担当者と期日つきで出す。** 期日が話に出ていなければ「期日未定」、担当者が特定できなければ「担当未定」。先方側のアクションも同じ表に書く。
4. **提案した内容（プラン・金額・期間）と先方の反応を必ず拾う。** 金額や条件はメモのとおり。提案が無ければ「提案なし」。
5. **3 つの成果物を分けて出す**（テンプレートは `references/output-templates.md`）。CRM には書き込まない。
6. （依頼されたときだけ）利用者が「この案のとおりに更新して」と依頼したら、案と同じ内容だけを書き込みのツールで反映する。
   確認画面の差分を人が見て許可する。

## 出力の型

1. **社内サマリー**: 論点 / 相手の優先事項 / 反論と対応 / 競合 / アクション（担当者｜期日）/ 次のステップ / 商談への影響（解釈なので事実の節と分ける）
2. **顧客向けフォローアップ**（プレーンテキスト。件名＋本文）: お礼 → 話した要点 → こちらが約束したこと → 期日つきの次のステップ
3. **CRM の更新案**: 変える項目だけを「現在の値 → 新しい値 → 根拠（メモの該当箇所）」で。
   議事録は議事録データベースにレコードとして追加し、企業へのリレーションを必須にする（単独のページを作らない）

```plain text
CRM の更新案（B ヘアサロン / 2 回目の商談）
- ステータス: 担当者検討 → 担当者合意
  根拠: オーナー「来月から始めたいので、見積をください」
- 次アクション: 提案資料の送付 → 見積の送付（期日: 今週金曜）
  根拠: 店長「今週中に見積をいただけますか」
- 獲得目標月: 変更なし
```

## 守ること

- メモに無いことを補わない。数値・社名・条件を変えない。担当者や期日を作らない。
- ステータスの遷移は案として出すだけ。「前向きに検討します」で進めない（遷移条件の事実に当たるかを人が判断する）。
- 会社名・案件名の略称を使わない（後で機械が同一視できない）。
- 顧客向けの文面に社内メモ（確度・懸念・競合の評価）を混ぜない。送信しない。

## フォールバック先

- **メモが短い・断片的**: 分かる範囲で 3 つを作り、足りない項目を確認事項として末尾に並べる。補って書かない。
- **CRM を参照できない**: 更新案の「現在の値」を「未取得」とし、新しい値と根拠だけを書く。
- **書き込みのツールが無い**: 更新案を人が手で反映できる形（項目ごとの新しい値の一覧）で渡す。
