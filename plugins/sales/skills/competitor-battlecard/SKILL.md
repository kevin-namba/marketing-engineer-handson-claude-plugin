# 競合の比較（バトルカード）

提案の工程（proposal-workflow）の工程 1 で、相見積りのときに company-brief と並列で動かす。単独でも使える。

## 最初に確かめること

- 自社は何を売っているか（1 行）と、料金表・実績の資料の場所。自社の情報は利用者が渡したものからだけ取り、分からなければ 1 回だけ聞く
- 比べる競合（最大 5 社。1 社あたり検索 10 クエリまで）。分からなければ、相手が商談で口にした社名を議事録から拾う
- どの商談のためか（相手の課題と、相手が重視する評価の軸）

## 手順

1. **競合を決める。** 同業他社 / 代替手段 / 内製 / 現状維持、に分けて並べ、相手の商談に関係するものだけに絞る。
2. **競合ごとに公開情報を調べる。** 自社についても同じ項目を、渡された資料で埋める。

   | 調べること | 検索の型 |
   |---|---|
   | 提供内容（範囲） | `[競合] サービス内容` |
   | 料金・契約の条件 | `[競合] 料金 プラン` / 公式サイトの料金ページ |
   | 実績・得意な業界 | `[競合] 実績 事例` |
   | 直近の動き（90 日以内） | `[競合] プレスリリース` / 公式のお知らせ |
   | 評判 | `[競合] 評判 口コミ`（二次情報として扱う） |

3. **社内の記録を読む**（参照できるとき。読み取り専用の MCP ツール → CSV・議事録 → 利用者が貼った情報の順）。
   失注・解約の理由に競合の名前が出ている案件、競合と比べられて受注した案件、相手が口にした反論を拾う。
   参照できなければ公開情報だけで進め、そう書く。勝率は件数が確認できたときだけ「N 件中 M 件」と書く。
4. **比較表とカードを作る。** 比較表は、相手が重視する評価の軸を行に、自社と各競合を列にし、
   各セルに「自社が有利 / 競合が有利 / 同等 / 未確認」を付ける。カードのひな形は `references/battlecard-template.md`。

## 出力の型

```markdown
# 競合の比較: [自社] vs [競合の一覧]（YYYY-MM-DD）
対象の商談: […]　情報源: Web の公開情報 / 社内の記録（参照できた範囲）

## 比較表
| 評価の軸 | 自社 | 競合 A | 競合 B | 内製 |

## 勝ちやすい場面・負けやすい場面
| 相手 | 自社が選ばれやすいとき | 競合が選ばれやすいとき |

## 競合ごとのカード
（references/battlecard-template.md の形）

## 未確認の項目
[項目・理由・確かめる方法]
```

提案の工程から呼ばれたときは、ファイルに保存し、戻り値はパスと要点 5 行以内にする。

## 守ること

- 料金・実績の数字は、一次情報（競合の公式サイト・公式の発表）か二次情報かを分ける。二次情報だけの数字には「要確認」を付ける。
  出典は実際の URL と取得日で残す。
- 確認できなかった項目は「未確認」、非公開の料金は「非公開」と書く。推測の金額を入れない。
- 競合が強い領域を正直に書く。競合の悪口を書かず、弱点は相手に確かめてもらう質問の形にする。
- 自社の強みの根拠は、利用者が渡した実績だけを使う。実績を作らない。
- このカードは社内用。相手に渡す資料にそのまま貼らない。

## フォールバック先

- **社内の記録を参照できない**: 公開情報だけで作り、勝ち負けの傾向は「未取得」と書く。
- **Web 検索が使えない**: 利用者が持っている競合の資料・サイトの URL を受け取って読む。
- **競合の名前が分からない**: 代替手段の種類（同業 / 別の手段 / 内製 / 現状維持）で比較表を作り、社名が分かった時点でカードを足す。
