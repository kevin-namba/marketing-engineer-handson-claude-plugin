# 広報とメディアリスト

メディアが取り上げるのは宣伝ではなくニュースである。リリースを書く → 載りそうな媒体を公開情報で確かめる →
媒体ごとに打診の文面を書く → 載ったら実測する、までを扱う。配信と送信は人が行う。

## 最初に確かめること

足りないものだけを 1 回でまとめて聞く。

- 何を発表するか（新商品・新店・調査結果・受賞・提携）と、発表日
- 材料: 価格・日付・経緯・数字（数字には出どころ。自社調べならサンプル数と期間）
- 商圏・業界（リストの範囲を決める）
- 使える素材（写真・データ・現地取材の可否・コメントを出せる人）と、問い合わせ先として載せてよい窓口

## 手順

1. **何で載るのかを先に決める**（新規性 / 時事性 / 地域性 / 社会性）。決めた切り口をタイトルに含める。
   どれも無ければ、リリースの前に**材料づくりを提案する**（自社データの調査結果化・周年や累計の節目・地域との接点・他社との協業）。
2. **リリースを書く。** 構成: 結論のタイトル（約 30 字）→ 5W1H のリード → 本文（背景 → 詳細 → 今後）→ 会社概要 → 連絡先。
   型と点検の項目は `references/release-and-pitch.md`。
3. **記者リストを公開情報だけで作る**（依頼に無ければ 10 件まで）。
   **各行に「同種の題材を扱った実記事の URL と日付」を付ける。** 根拠の無い媒体は載せない。

   | 当たり先 | 見つけ方 |
   |---|---|
   | 地域メディア（地方紙・地元のテレビ局・タウン誌） | 商圏の地名と「掲載」「特集」で検索し、同じ種類の題材を実際に載せた媒体から並べる |
   | 業界の専門 Web メディア | 同業他社が掲載された記事から辿る |
   | 記者や編集者個人 | 署名記事と公開されているプロフィールから探し、その人が書いた実際の記事と一緒に記録する |

4. **連絡先は公開されている窓口だけ**（リリースの受付・情報提供フォーム・公開されたメールアドレス）。見つからなければ「窓口: 未確認」。
5. **打診の文面を媒体ごとに書く。**「なぜこの媒体なのか」を過去の実際の記事に触れて 1 行で書き、記者が使える素材をはっきり書く。
   原稿・リスト・文面を返して止まる（送る手順は案内する）。
6. **掲載後は実測する。** 指名検索の変化（Search Console で、ブランド名のクエリを掲載の前後の同じ長さの期間で比べる）/
   被リンク（掲載ページを開いて確かめる）/ 言及の波及 / 掲載面の実物（URL・掲載日・媒体名）。
   売上への寄与は、計測が繋がっていなければ「未計測」。

## 出力の型

```markdown
# 広報の成果物: [題材]（YYYY-MM-DD）

## 切り口
[新規性 / 時事性 / 地域性 / 社会性] — 理由 1 行

## プレスリリース（原稿）

## メディアのリスト（N 件。送信はしていない）
媒体: 〇〇タウン情報（月刊のタウン誌。Web 版あり）
根拠: 2026-07-15「夏の新作和菓子 5 選」で市内の和菓子店 3 軒を掲載（記事の URL）
窓口: 公式サイトの情報提供フォーム（公開）
切り口: 地元の農家との取り組み。季節の特集に合わせて 9 月中旬に打診する
未確認: 10 月号の締切（公式サイトに記載なし）

## 打診の文面（媒体ごと）
## 探し方の手順（リストが薄いとき）
## 人が行うこと
[配信サービスへの入稿 / 各窓口への送信 / 確認が要る表現]
```

## 守ること

- 出典の無い「業界初」「地域最大」「No.1」を書かない。
- 数字には検証の状態（自社調べ・サンプル数・期間）を添える。
- 確認できなかった項目は「未確認」と書く。締切や担当者名を作らない。非公開の個人連絡先を推測・収集しない。
- 一斉送信の文面を作らない。送信・配信はしない。
- リストが薄い地域でも成果物を空にしない（確認できた媒体＋探し方の手順）。

## フォールバック先

- **Web 検索が使えない**: リリースの原稿と材料づくりの提案だけを作り、リストは探し方の手順として渡す。
- **ニュースになる材料が無い**: 材料づくりの案を、必要な準備と期間を添えて出す。
- **Search Console を参照できない**: 管理画面から CSV を出す手順を案内し、指名検索の変化は「未計測」と書く。
