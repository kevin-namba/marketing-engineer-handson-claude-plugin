# 事例調査

提案で納得してもらえる型は「これをやったことがあります」（自社の実績）と
「他社でこれが成果を出していて、自社でも再現できます」（他社の事例 × 自社の資産）の 2 つ。この Skill は 2 つの材料を 1 回の調査で揃える。

## 先に埋める与件（6 項目）

対象 / 課題 / 目的の指標 / 施策の種類 / ターゲット / 制約。

```yaml
与件:
  対象: 温泉旅館（客室 30 室・個人経営）
  課題: 平日の稼働率が低い。予約の 8 割が予約サイト経由
  目的の指標: 平日の直接予約数
  施策の種類: [インフルエンサーの起用, アカウント運用]
  ターゲット: 首都圏に住む 30〜40 代の夫婦
  制約: 月の予算は 30 万円まで。撮影は平日のみ
```

提案の工程（proposal-workflow）から呼ばれたときは与件サマリーを受け取る。単独で呼ばれて足りなければ、
議事録から補うか、依頼した人に 1 回だけ確認する。課題・施策・指標まで絞ってから探す（広いままだと数字の無いまとめ記事ばかり集まる）。

## 手順

0. **自社の実績と資産を先に押さえる。** 案件の台帳・議事録・実績レポート・提案資料・提携先の台帳から、似た課題の案件と結果、
   依頼できる人・制作体制を取る（読み取り専用の MCP ツール → CSV・ファイル → 利用者が貼った情報の順）。
   取れなければ他社の事例だけで進め、「社内の実績は未取得」と書く。
1. **調査先を 4 種類に分ける**（支援会社 / 事業会社 / 業界メディア / 広告のアーカイブ）。
   探し方と検索クエリの型は `references/research-sources.md`。
2. **2 段階で読む。** 一覧は最後まで辿るが抜くのは見出し・業界・施策の種類だけ、与件に合う本命だけ精読する。上限は 5 社 × 5 件。
   検索結果の記事 1 本で満足せず、その会社の事例一覧に入る。
3. **同じ事例を 1 件にまとめる。**「事業会社名 × 施策 × 時期」をキーにし、事業会社側の発表を正とする。
   食い違いが提案の判断に効くときは両方を書いて「要確認」にする。
4. **1 件ずつ同じ形式で記録する**（下の例。架空の事例）。与件との近さは業界・課題・指標・施策の一致数で、
   再現できるかは自社の資産に照らして、高・中・低と理由を書く。
5. **数字の無い事例は優先度を下げる**（捨てずに、施策の形式の参考として残してよい）。

```yaml
- タイトル: 温泉旅館 × 旅行系インフルエンサー 3 名の平日宿泊企画
  主体: 事業会社の発表（支援会社の事例ページにも掲載）
  課題: 平日の稼働率
  施策: 平日限定プランを 3 名が宿泊レポートで紹介
  成果: 平日の直接予約が前年同月比 +38%（事業会社の発表）
  出典: https://www.example.com/news/（取得日 2026-09-20）
  与件との近さ: 高
  再現できるか: 中（すぐに依頼できるインフルエンサーは 2 名まで）
  提案での使い方: 「平日限定プラン × 2 名の宿泊レポート」に縮めて提案する
```

## 出力の型

結論（提案の切り口）を先に、記録を後に置く。

```markdown
# 事例調査: [対象 / テーマ]（YYYY-MM-DD）
## 与件サマリー
## 提案の切り口（結論）
1. 【やったことがある型】[自社の実績] → [提案]
2. 【他社で成果が出ていて再現できる型】[他社の事例] × [自社の資産] → [提案]
## A. 他社の事例（近さ・再現できるかの順）
| # | 事例 | 主体 | 施策 | 成果 | 近さ | 再現できるか | 出典（取得日） |
## B. 自社の実績と資産
（課題 → 企画 → 結果。URL 付き。取得できなかった場合は「社内の実績は未取得（理由）」）
## 調査の記録
見た範囲（会社名: 一覧 N 件中 M 件を確認、精読 K 件）/ 使った情報源 / 見ていない範囲 / 次に調べる価値があるもの
```

提案の工程から呼ばれたときは、レポートをファイルに保存し、戻り値はパスと要点 5 行以内にする。

## 守ること

- 一覧が最後まで辿れないときは「一覧 N 件中 M 件を確認」と母数を書く。見ていない範囲を調査の記録に必ず書く。
- 社内の実績を取得できなかったときに「実績なし」と書かない（取得できなかったことと、実績が無いことは別の事実）。
- 出典は後から開ける実際の URL と取得日で残す。載っていない数字（広告のアーカイブの出稿額や再生数）を書かない。
- 事例の成果の数字を、相手に約束できる数字として書かない。条件の違いを添える。
- Instagram と TikTok の画面を自動で取りに行かない。必要な数字は人が画面で確かめたものを使うか「未取得」と書く。

## フォールバック先

- **ページが取得できない**: 本命の事例の URL か本文を利用者に渡してもらう。取れなかった会社は調査の記録に書く。
- **Web 検索が使えない**: 利用者が持っている事例の URL・資料を受け取り、手順 3〜5 だけを行う。
- **与件に合う事例が足りない**: 近い業界・近い施策まで 1 段だけ広げ、広げたことを調査の記録に書く。
