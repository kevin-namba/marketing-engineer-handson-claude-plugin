# 商談前のブリーフ

商談の準備を 1 画面にまとめる。目的は「何を聞くか」と「前回の約束を忘れていないか」を商談の前に確かめること。

## 最初に確定すること

会社名 / ミーティングの種別（初回ヒアリング・提案・交渉・定例）/ 参加者（氏名と役職）/ 背景メモ（あれば）/ 今回のゴール。
分からなければ最初に聞く。ゴールが指定されていなければ、種別から 1 つ仮置きして「ゴール（仮）」と書く。

種別で力点が変わる。

| 種別 | 力点 |
|---|---|
| 初回ヒアリング | 話すより聞く。相手の状況・課題・優先事項を理解する |
| 提案 | 相手に固有の使い方と、それに合う事例を見せる |
| 交渉 | 懸念への対応、価値の根拠 |
| 定例 | 提供した価値の確認、拡大の機会 |

## 手順

1. **CRM を読み取り専用で引く。** 商談の行からステータス・確度・次アクション・担当者・流入元。
   議事録データベースから前回の約束事（誰が・何を・いつまでに）・未解決の質問・出た反論・競合への言及。
   データの構造を推測せず、会社名で検索して実体を確かめてから読む。完了の記録が無い約束は「未完了（記録なし）」。
2. **過去の提案資料を探す。** 資料置き場から、この会社に出した提案資料・見積を探し、プラン・金額・期間・日付だけを抜く。無ければ「なし」。
3. **業界の SSOT を Web より先に引く。** ペイン・出典付きの数値・定番のヒアリング項目・想定反論。
   数値は信頼度ラベルと調査年を一緒に引き継ぐ。SSOT が無ければ数値を使わず、質問は `references/brief-template.md` から選ぶ。
4. **Web で足す**（5 クエリ前後）。直近 30 日のニュース、参加者の公開情報、店の SNS の最近の投稿（利用者の記録から。無ければ「未取得」）。
5. **足りない情報は推測で埋めず、商談で確認する質問 5 つに変える。** 相手の状況 → 課題 → 意思決定の順に並べ、すでに答えが分かっている質問は入れない。
6. アジェンダを時間配分つきで書く（オープニング → 本題 1〜2 個 → 期日つきの次のステップ）。

## 出力の型（1 画面）

前回の約束のうち未完了のもの / 今回のゴール 1 つ / アカウント概要（表）/ 面談相手ごとの役割と話のきっかけ /
アジェンダ（時間配分つき）/ 確認する質問 5 つ / 想定される懸念と**具体的な**答え方 / 社内メモ

テンプレートと業種ごとの定番の質問は `references/brief-template.md`。

## 守ること

- 前回の約束のうち未完了のものを先頭に出す。
- 1 画面に収める。収まらない材料は削るか質問に変える。
- 懸念への答え方は具体的に書く。使う数字・事例は、承認済みの実績か業界の SSOT にあるものだけ。材料が無ければ「持ち帰る」と書く。
- SSOT に揃っている材料を Web で調べ直さない。
- CRM に書き込まない。Instagram と TikTok のページを自動で開かない。

## フォールバック先

- **CRM を参照できない**: 会社・種別・参加者・背景の 4 つを聞き、Web だけで作る。前回のメモは貼ってもらう。
  貼られなければ「前回の約束: 未取得」と先頭に書く。
- **公開情報が薄い**: 質問を多めに出す（ブリーフの目的は「何を聞くか」を決めること）。初めての相手なら `company-brief` を先に回す。
- **参加者が分からない**: 役職だけで書き、最初の質問に「本日の参加者と役割の確認」を入れる。
