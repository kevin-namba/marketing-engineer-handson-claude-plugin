# 提案資料の工程

提案資料づくりは複数の工程の受け渡しである。この Skill が持つのは工程の順番・受け渡し・省略の可否だけで、各工程の中身は担当の Skill に任せる。
人が判断するのは提案概要の承認の 1 箇所（工程 4.5）。承認を得る前に資料の作成に着手しない。

## 工程と担当（出力は次の工程の入力。ファイルで受け渡す）

作業フォルダを案件ごとに決め（例: `proposals/<企業名>_<YYYYMMDD>/`）、中間成果物はすべてここに置く。

| 工程 | 担当 | 出力（ファイル） |
|---|---|---|
| 0 与件把握 | メインの会話（CRM の商談と議事録、業界の SSOT を読む） | 与件サマリー（`00-brief.md`） |
| 1 企業調査 | company-brief（相見積りなら competitor-battlecard を並列） | 調査レポート（`01-company.md`、`01-competitors.md`） |
| 2 事例調査 | case-research | 提案の切り口と事例集（`02-cases.md`） |
| 3 施策の熟考 | 企画系の Skill で案を出し、採点して絞る | 採点済みの案（`03-ideas.md`） |
| 4 ストーリー構築 | 提案戦略のエージェント（`proposal-strategist`） | 提案の骨子（`04-outline-full.md`、初回なら `04-outline-first.md`） |
| 4.5 提案概要の登録と承認 | メインの会話。議事録データベースに概要ページを作り、企業へのリレーションを貼る | 承認済みの概要ページ。**人の承認（ゲート）** |
| 5 資料作成 | 原本（マスター）の複製。補助に quote・HTML アセット | 資料・見積 |
| 6 品質チェック・商談準備 | デザイン点検 → call-prep → 商談後は call-summary | 商談メモ（CRM へ戻す） |

与件サマリーと提案概要ページの型は `references/brief-and-overview.md`（工程 0 と 4.5 の前に読む）。

## モード

| モード | 使いどころ | 回す工程 |
|---|---|---|
| フル | 新規の業界・大型案件・稟議が要る相手 | 0 → 1 → 2 → 3 → 4 → 4.5 → 5 → 6 |
| 標準 | 通常の新規提案 | 0 → 1 → 2 → 4（3 は事例調査の切り口で代替）→ 4.5 → 5 → 6 |
| クイック | 商談直前・既存クライアントへの追加提案 | 0 → 1 → 2（自社実績のみ）→ 4.5 → 5 |

**省略できない工程: 1・2・4.5・5**。どのモードでも承認のゲートは飛ばさない。
起動したら与件と商談のステージを確認してモードを提案し、合意してから進める。各工程の終わりに中間成果物を 1 画面で示す。

## 手順の要点

- **0 与件把握**: 6 項目（対象 / 課題 / 目的の指標 / 施策の種類 / ターゲット / 制約）に商談の状況と出典を添えて 1 枚にする。
  足りない項目は議事録から補うか、依頼した人に 1 回だけ確認する。
- **3 施策の熟考**（フルだけ）: 与件の施策の種類に合う企画系の Skill だけを選ぶ。
  経営課題への直結度 × 競合のいない余地の大きさ × 自社の強みとの適合、の重なりで絞る。
- **4 ストーリー構築**: エージェントに与件サマリー・調査レポート・事例集・採点済みの案・自社の料金表のパスを渡す。
  料金は自社の料金表からだけ組む。料金表が無ければ、料金案を作る前に聞く。
- **4.5 承認**: 書き込みの前に、作るページの内容と紐付け先を見せて確認を取る。ページの URL を示し、人の明示的な承認を得る。
  修正の指示があれば工程 4 に戻す。資料の完成後、同じページに資料と見積の URL を追記する。
- **5 資料作成**: 着手前に、中核のスライドが原本のレイアウトで作れるかを確かめる。見積は quote に料金案と宛先を渡す。
- **6 品質チェック**: 1 スライド 1 メッセージか / 数値に出典と信頼度ラベルがあるか / 社名・固有名の誤りが無いか /
  別の企業向けの記述が残っていないか。

## 委任のきまり

- 調査系の工程（1・2・3）はサブエージェントに切り出す。メインは指揮と品質確認に徹する
- サブエージェントは結果を先にファイルへ保存し、戻り値はパスと要点 5 行以内
- 同時に動かすのは 3〜4 体まで。サブエージェントからの再委任は禁止
- CRM・資料置き場への書き込みと破壊的な操作はメインの会話で行う（サブエージェントに持たせない）

```
[Skill 名] の Skill を使って、次を実行してください。
与件: [与件サマリーの全文]
前の工程の成果物: [パス]（作業の前に必ず読む）
出力: [出力先のパス] に Markdown で保存する。
サブエージェントは起動せず、自分で完結させる。CRM や資料置き場には書き込まない。
作業が終わったら先にファイルへ保存し、その後にパスと要点 5 行以内だけを返す。
```

## 守ること

- 原本を直接編集しない。複製してクライアント別のフォルダへ移す。
- 原本に無いレイアウトが中核になるなら、着手前に別経路（HTML → PDF / PPTX）を判定して人と合意する。
- 既存クライアントへの提案では、原本の匿名の実績カードに相手自身の実績が無いかを複製の前に確認する。
- 数値には信頼度ラベルを付ける。業界ごとの「使ってはいけない数値」を使わない。
- 骨子はフルで作り、初回提案は引き算版に絞る（柱 1 本・課題 7 割・提案 3 割・最小リスクの試行で締める）。捨てた柱は次回の与件として残す。
  提案資料と見積の送付は人が行う。

## フォールバック先

- **原本の置き場が使えない**: HTML から PDF / PPTX を作る（着手前に人と合意する）。
- **CRM が使えない**: 概要を Markdown で出して承認を取り、CRM への登録は後追い（ゲート自体は省略しない）。
- **サブエージェントを使えない**: メインの会話で工程を順に行う。調査の結果は必ずファイルに保存し、会話には要点 5 行だけを残す。
- **企画系の Skill が入っていない**: 工程 3 を飛ばし、事例調査の切り口で代替する。
