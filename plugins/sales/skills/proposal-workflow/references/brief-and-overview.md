# 与件サマリーと提案概要ページの型

## 与件サマリー（工程 0 の出力。`00-brief.md`）

後ろのすべての工程の入力になる。6 項目に商談の状況と出典を添えて 1 枚にする。

```yaml
与件:
  対象: 温泉旅館（客室 30 室・個人経営）
  課題: 平日の稼働率が低い。予約の 8 割が予約サイト経由
  目的の指標: 平日の直接予約数
  施策の種類: [インフルエンサーの起用, アカウント運用]
  ターゲット: 首都圏に住む 30〜40 代の夫婦
  制約: 月の予算は 30 万円まで。撮影は平日のみ
  商談の状況: 担当者検討（初回ヒアリング済み）
  出典: 初回ヒアリングの議事録（CRM）
```

続けて次を添える: 過去の接点（日付・話したこと・約束したこと）/ 相手の言葉（議事録の言い回しをそのまま引用）/
業界の数字（出典・調査年・信頼度ラベル付き）/ 競合の有無 / 意思決定（誰が・いつまでに）/ 未取得の項目 / モードの提案と理由。

足りない項目を推測で埋めない。与件は、課題・施策・指標の 3 つが 1 文で言える粒度にする。

## 提案概要ページ（工程 4.5。CRM の議事録データベースに作る）

- タイトル: `[企業名]｜提案概要（YYYY-MM-DD）`
- 企業へのリレーション: 必須。提案先が CRM に未登録なら、利用者に確認して先に企業のレコードを作ってから紐付ける

```markdown
## 与件サマリー
[00-brief.md の要点]
## ウィンテーマ
[1〜3 行。相手の課題 → 自社の強み → 根拠]
## 提案の柱と施策の概要
| 柱 | 施策 | 指標（仮置き） |
## 想定の料金
[自社の料金表のどのプランか。幅で示す場合は幅]
## ストーリーの骨子
[章立てと想定の枚数]
## 参照する事例
- 自社の実績: […]（URL）
- 他社の事例: […]（URL・取得日）
## 今回は出さないもの（次回の与件）
[捨てた柱と理由]
## 次のアクション
[承認後に作るもの・担当・期日]
## 成果物（資料の完成後に追記）
- 提案資料: [URL] / 見積: [番号・URL]
```

「進めてよい」という明示的な返答を承認とする。返答が無い・あいまいなら着手しない。
CRM が使えず Markdown で承認を取ったときは、登録が後追いであることを最後の報告に書く。
