# シグナルの定義ファイル

「誰の・どんな一文を『探している』とみなすか」を文章にして保存し、毎回同じものを使う。

## ひな形

```yaml
signal_definition:
  対象: （誰の投稿・どんな会社の情報か。地域・業種・規模）
  拾う一文:
    探索: （「〇〇 おすすめ」「〇〇を探してる」「外注先を検討」など、実際に使われる言い回し）
    競合への不満: （「予約が取れない」「対応が遅い」など）
    ライフイベント: （引っ越し・記念日・旅行の計画。BtoB では担当者の異動・着任、予算期の発言）
  除外:
    - 同業者や事業者のアカウントの投稿
    - （何日より前の投稿か）
    - 既存のお客様（顧客名簿と突き合わせる）
  温度:
    高: 日付や期限がある
    中: 探しているが時期が決まっていない
    低: 感想や願望
  探す場所:
    自動で見る: （ニュース検索の固定クエリ、求人ページ、自治体の公報、質問サイト。規約を確認済みのものだけ）
    人が記録する: （Instagram・TikTok・X の検索語とハッシュタグ。人がアプリで検索して記録表に追記する）
  変更記録:
    - {日付: YYYY-MM-DD, 内容: （何をどう変えたか）}
```

ゼロ件が続いて定義を広げるときは、地域・語彙・見る場所のうち 1 回に 1 つだけ変える。

## シグナルの型

| シグナルの型 | 例 | どこで拾うか |
|---|---|---|
| 事業の変化 | 新規オープン・リニューアル・出店 | ニュース検索・プレスリリース配信サイト・自治体の公報 |
| 投資の余力 | 採用募集の増加・担当職の求人 | 求人サイト・公式サイトの採用ページ（求人票の本文まで読む） |
| 探索の声 | 「近くでおすすめの店は」「外注先を探している」 | SNS の公開投稿（人が検索して記録する）・質問サイト |
| 競合の顧客 | 競合の導入事例ページ、競合への不満の投稿 | 競合の公式サイト・レビューサイト・SNS |
| 公募・依頼 | 自治体や公共団体のプロポーザル | 公募情報サイト・自治体サイト（巡回は `tender-scouting`） |

## 記録表（人が追記する表）の列

| 列 | 内容 |
|---|---|
| observed_at | 人が見た日時 |
| platform | 媒体名 |
| url | 投稿の URL |
| author | 表示名（個人を特定する情報は必要な範囲に留める） |
| quote | 原文の引用（そのまま貼る。要約しない） |
| search_term | どの検索語・ハッシュタグで見つけたか |
| memo | 補足（任意） |

温度と理由は人が付けなくてよい（Skill が定義ファイルの基準で付ける）。
