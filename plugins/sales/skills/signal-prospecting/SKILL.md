# 見込み客の検知

探すのは「この業種の会社を全部」ではなく「いま買う理由がある相手」。公開の投稿・ニュース・求人から兆し（シグナル）を拾い、
原文と根拠を付けたリード一覧と、返信の下書きまでを作る。探している人は数日で決めてしまうので、定期実行（毎日〜週 2 回）に載せて使う。

## 先に固定する（定義ファイル）

対象 / 拾う一文 / 除外 / 温度の基準 / 探す場所の 5 つ。ひな形と記録表の列は `references/signal-definition.md`。
無ければ利用者と埋めてから進む（対象と拾う一文が決まらないまま探さない）。
**定義を変えたら、変えた日と内容を記録する**（件数の増減の理由を切り分けるため）。

## 手順

1. **前回のリストを前回の成果物から取り直す**（ファイル・スプレッドシート・CRM のリード一覧）。
   初回は「初回なので突き合わせなし」と明記する。記憶や推測で前回分を再現しない。
2. **探す。** 規約が自動の取得を禁じている面（Instagram・TikTok・X）は、**人が探して記録した表を読む**。
   自動で見るのは、公式 API で許可された範囲と、規約で自動収集が禁止されていない情報（ニュース・プレスリリース・自治体の公報・求人ページなど）だけ。
   クエリは定義ファイルに固定したものを使う。開けなかった面は「未取得」と書き、「該当なし」と区別する。
3. **各行に原文の引用・URL・観測日時・シグナルの型・温度・理由 1 行を付ける。** 原文の無い行は載せない。
4. **温度は行動の近さで付ける。**

   | 温度 | 基準 | 例 |
   |---|---|---|
   | 高 | 日付や期限がある | 「今週末に行く店を探している」「今期中に外注先を決めたい」 |
   | 中 | 探しているが時期が決まっていない | 「おすすめを教えてほしい」「比較検討している」 |
   | 低 | 感想や願望 | 「いつか行きたい」「あったらいいのに」 |

5. **除外し、新着だけを上に出す。** 除外リスト（既存のお客様・アプローチ済み・お断り）と定義の「除外」を適用し、前回のリストと突き合わせる。
   キーは URL。企業単位で数えるときは法人名＋ドメイン。

   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/skills/signal-prospecting/scripts/diff_leads.py \
     --previous previous.csv --current current.csv --key url --out merged.csv
   ```

   新着の行に返信の下書きを付ける。最初の返信は売り込みではなく、その人の質問に役立つ答えと名乗りにする。
6. **（任意）営業に渡す順番を付ける。** AI に「有望な順に」並べさせず、重みの設定から足し算で点数を出す。
   重みの JSON の形は `references/lead-scoring.md`。

   ```bash
   python3 ${CLAUDE_PLUGIN_ROOT}/skills/signal-prospecting/scripts/lead_score.py \
     --leads leads.csv --weights weights.json --out scored.csv
   ```

## 出力の型

```markdown
# 見込み客の検知: YYYY-MM-DD
定義ファイル: （ファイル名・最終変更日）
前回との突き合わせ: あり（前回 YYYY-MM-DD）/ 初回なので突き合わせなし
未取得の面: （開けなかった・記録が無かった場所と、その対処）

## 新着（N 件）
| 温度 | 型 | 原文の引用 | URL | 観測日時 | 理由（1 行） |

## 返信の下書き（新着のみ。送信は人が行う）
## 継続（前回も載っていた行）
## 除外した行と理由
## 次の一手
- （温度「高」の行から company-brief に回す候補。ゼロ件のときは定義の広げ方）
```

## 守ること

- **ゼロ件は正常な結果**。「今回はゼロ件でした」と明言し、定義の広げ方（地域・語彙・見る場所）を提案して終える。
- 件数を稼ぐために低い温度を高く見せない。
- 返信は下書きまで。一斉送信の文面を作らず、行ごとに原文に触れた個別の文面を書く。
  企業の公式アカウントとして名乗る（個人を装った推薦は規制の対象）。競合を悪く言わない。
- 送信しない。送るかどうか・いつ送るかは人が決める。

## フォールバック先

- **人が記録した表が無い**: 自動で取れる面だけで進め、SNS の面は「未取得」と書いて、記録表のひな形を渡す。
- **前回のリストが読めない**: 「突き合わせなし」と明記して今回分だけを出す。次回のために保存先を利用者と決める。
- **除外リストが読めない**: 除外を適用していないことを出力の冒頭に書く。
- **Web 検索が使えない**: 利用者が貼った投稿・記事の一覧に、温度・理由・下書きを付けるところだけを行う。
